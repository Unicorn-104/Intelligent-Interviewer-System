# 企业端系统消息

## 界面与使用

消息中心顶部始终固定“系统消息”，包含独立铃铛图标、最新通知标题、时间及真实未读数；即使没有通知或没有普通聊天，也能进入通知页。加载失败显示错误并可重试，不把错误当作空列表。

从消息中心进入系统消息后，主页面直接以左侧绿色铃铛、右侧白色圆角气泡展示每条通知全文，时间置于气泡框外下方；不再先显示卡片摘要列表。顶层导航打开该页，隐藏主界面的底部Tab导航，底部固定“系统通知无需回复”。气泡中标题用于区分不同业务事件，未读点和点击标记单条已读保持原逻辑。点击通知仍可进入单条详情；改期申请保留原审批跳转。详情参考C-APP通知样式：返回按钮、主标题与“系统通知”副标题、左侧绿色系统铃铛、白色圆角气泡、气泡下方时间、底部固定“系统通知无需回复”。正文可选择复制，长内容可滚动，不提供输入框或回复；铃铛与消息列表共用同一组件。支持分页、下拉刷新、前台约30秒静默刷新，后台/页面被覆盖不轮询，退出后释放定时器。底部提示“系统消息仅用于通知，无需回复”，没有输入框、发送或快捷回复。原改期通知可继续进入已有审批页面，该业务操作不属于回复系统消息。

## 通知来源

复用现有t_msg及/system/im/notifications接口，不增加表或字段。服务端按真实已提交业务记录补齐：

| 事件 | 条件与去重 |
| --- | --- |
| 收到新的简历投递 | 当前企业岗位的t_app_record，最近7天，接收账号+投递ID |
| 面试即将开始 | 预约状态0/1，距离开始0至60分钟，接收账号+预约ID+当前开始时段 |
| 面试安排已确认/已取消 | 当前企业预约状态1/2且最近7天更新，接收账号+预约ID+状态 |
| 面试报告已生成 | 当前企业面试已有t_int_evaluation且最近7天创建，接收账号+报告ID |

通知带候选人名称和岗位标题，不复制简历原文、聊天原文、会议链接或模型评分。通知均为站内只读内容，不发送IM、不发送邮件、不修改原面试或投递状态。不使用旧邮件任务的apt_notified/ofr_notified字段；旧邮件任务不在本功能范围。

首轮允许补齐近7天真实事件；未来提醒只在开始前60分钟生成。只通知当前有效企业绑定和启用账号，企业ID从服务端绑定解析。每次刷新锁定接收账号行，事件去重与批次插入在同一事务，重复刷新/并发定时扫描不重复通知，已读通知不重新变未读。改期后的新开始时段可产生新提醒，已取消或已过时场次不会生成临近提醒。

后台每60秒按账号游标轮转，每轮最多100个有效企业账号；每账号每事件种类最多50条未通知事件，后续继续补齐。通知列表首屏读取前补齐当前账号事件，翻页不重复扫描。某个账号失败不会阻断其他账号，异常日志不含个人数据或原SQL。

业务事件标识使用/enterprise/system-events/...格式；客户端不把它当作任意网页打开，而是按当前登录身份调用专用详情解析接口，重新校验通知接收人及当前企业业务归属。通知详情由系统消息页自身展示，原鉴权、当前接收人过滤、游标分页和已读接口继续复用。

## 2026-10-27 主入口样式修正

上次仅将单条详情改成气泡，用户从主入口仍看到卡片列表。此次改为系统消息主页面本身直接渲染统一通知气泡，详情复用SystemNoticeBubble与SystemNoticeFooter；由rootNavigator打开，底部主导航不再出现在系统通知页。

新增从消息中心点击进入后的直接气泡、全文不截断、头像在框外左侧、时间在框外下方、没有Card/ListTile，以及嵌套导航隐藏底栏和返回恢复的回归验证。相关34项测试、静态检查通过。此次仅修改e-app界面与文档，无Backend或数据库变更。

## 2026-10-27 关键信息与查看详情

气泡高亮明确标注的候选人/申请人、岗位/职位字段值，以及时间与已确认/取消/生成等状态；保持通知原文、紧凑字号与行距。底部增加小字号“› 查看详情”，与点击气泡阅读全文分开。

GET /enterprise/system-notices/{messageId}/destination只接受通知ID，从登录态取得账号、从当前有效企业绑定取得企业，不接受客户端指定候选人或企业。只查询当前接收人的t_msg目标；严格白名单解析既有事件标识，再按目标岗位当前企业限定查询真实投递、预约或报告。外部URL、畸形路径、已删除目标、跨企业或他人的通知均拒绝。

投递链接进入关联candidateId的TalentDetailPage并携带真实positionId；面试链接复用JobInterviewsPage且只加载该通知对应appointmentId，刷新时重新解析；报告链接展示该evaluationId对应的真实会话报告，读取已有评分/总结/维度，无模拟数据或报告生成操作。改期申请继续进入原审批页；未关联业务的旧普通通知回退到通知全文。业务解析成功后才标记单条已读，失败留在系统消息页并提示原因。未改动原API签名，无数据库DDL。
