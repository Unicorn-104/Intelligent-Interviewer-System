- 点击 chip 沿用原状态赋值及筛选回调，未改变数据源、筛选规则、扫描上限或分页行为；标签操作保持原实现。

## 数据与筛选

实施前只读核实 t_tal 全表15条，未按企业过滤。列表接口仍由服务端限制当前企业范围，客户端不扩大访问范围。

- 关键词与标签：复用 searchTalentPool，通过现有 keyword/tag 参数服务端过滤；标签精确匹配。关键词输入支持姓名/手机号，标签建议来自已加载记录，在标签筛选弹窗中显示，也可手输未出现的标签名。
- 状态：客户端按真实 status=0～9 精确筛选；不将候选人状态当作岗位招聘阶段。
- 每次请求20条。普通模式每次读一页、手动加载更多；按 talentId 去重，保持服务端顺序及首次出现的行。
- 选择状态后，每次筛选从第一页起最多读3页，遇短页提前结束；此模式不提供加载更多。
- 第3页仍满20条时，显示“结果较多，请补充关键词”，并说明仅检查前3页、结果可能不完整；不请求第4页。恰好60条时也保守显示该提示，因为现有封装不返回 total，无法在不读取第4页的情况下证明完整。
- 前3页没有匹配但扫描达到上限时，同样显示缩小范围提示，不冒充全局无结果。
- 现有 API 只返回 rows，界面只展示已加载人数，不虚构总数。普通模式满页允许下一页，短页或空页结束。
- 切换关键词/状态/标签或刷新后重置分页。未提交的新搜索输入不会改变加载更多使用的已生效条件。

## 四态与保护

首次加载或重新筛选显示骨架；全部条件确实扫描完且为空时显示“暂无候选人”或“当前条件无匹配”；首次加载/有界扫描失败显示 PageMessage 和重试。普通模式加载更多时显示底部进度，失败保留原列表及页码，底部重试同一页。

加载更多期间重复请求被阻止。请求序号防止旧搜索或旧分页响应覆盖新筛选；离开页面后的响应不更新已销毁页面。状态有界扫描失败不发布部分结果，重试从第一页重新读取。

候选人卡展示姓名、真实状态、求职方向、标签和通用评分。缺少评分显示暂无评分数据，不补零；不推导投递时间或岗位招聘阶段。详情跳转不传 jobContext，保留人才库直接进入兼容。

- 数据源：20条分页、关键词标签参数、普通模式页码、同页/跨页去重与顺序、短页/空页、跨页状态筛选、状态0与null区分、3页上限、有界无匹配、失败重试、无效响应/编号和非法请求参数。
- 页面：标题/别名、状态组件、搜索/标签/状态组合、标签手输/取消/空结果保留、清除条件、四态、分页失败保留/重试、分页进度、三页上限、旧搜索/分页迟到响应、退出保护、详情无岗位上下文与返回状态、窄屏/横屏。
- Chips：11个选项、横向滚动、文字、选中/未选中底色与文字色、共享图标颜色、点击状态及全部恢复。
- 入口：候选人管理可打开并返回，人才库别名保留，其他演示入口断言不变。

测试使用有限帧 pump 推进 chip 交互，不等待刻意未完成分页请求的 loading 动画结束。别名测试精确匹配“人才库 · 当前企业全部候选人”，状态“人才库”chip单独验证，保留唯一匹配及原业务断言。
