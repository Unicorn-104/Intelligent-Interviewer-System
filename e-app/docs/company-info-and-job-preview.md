# 企业信息管理、岗位预览与删除、岗位卡片整理

## 1. 企业信息管理（我的 → 企业管理 → 企业信息）

企业招聘者在「我的」页面维护求职者可见的企业对外展示资料，字段与
C-APP 企业主页（`GET /app/companies/{id}`）同源：

- 可编辑：企业名称、所属行业、企业规模、所在城市、详细地址、官网、
  企业简介、Logo 地址。
- 不可编辑：认证状态、信用代码等认证类字段由平台管理员维护。

接口（Backend `EnterpriseSettingsController`，需企业登录态）：

- `GET  /system/enterprise/settings/company` —— 当前绑定企业资料。
- `PUT  /system/enterprise/settings/company` —— 保存资料并返回最新值。

安全约束：

- 企业归属严格校验（`requireCompanyId`）：未绑定企业的账号直接 403，
  不回落默认公司，避免看到或修改其他企业资料。
- 名称必填且 ≤100 字；行业/规模/城市/地址/官网/简介/Logo 有各自长度上限；
  名称唯一冲突返回友好提示，不泄露数据库错误。
- 不修改 `cmp_verify_status`、`cmp_status`、`cmp_credit_code`。

## 2. 岗位预览（岗位详情 → 预览）

打开求职者视角的岗位预览页（`JobPreviewPage`），数据与求职者端同源：
`GET /agent/v1/jobs/{jobId}`（岗位公开详情接口，登录即可读）。

- 页面复刻 C-APP 职位详情布局：标题、薪资、城市/经验/学历、职位描述、
  任职要求、企业卡片（行业/规模/城市/简介）。
- 顶部标注「求职者视角预览」，底部「立即投递」为禁用预览态；
  预览页不提供投递、收藏、联系候选人等真实操作。
- 岗位 id 与请求不一致、接口异常时展示错误并支持刷新，不伪造数据。

## 3. 删除岗位（岗位详情 → 删除岗位）

删除范围按「仅无业务数据可删」设计：

- 后端 `DELETE /system/enterprise/jobs/{posId}` 删除前统计该岗位的
  投递（t_app_record）、流程实例（t_process_instance）、面试
  （t_sch_appointment）；任一存在则拒绝并提示改用停招/下线，
  不级联删除真实业务数据。
- 任何岗位状态（草稿/在招/暂停）只要无业务数据均可删除；
  外键约束作为兜底保护，技能关联先行清除，事务回滚保证不误删。
- 客户端删除前弹二次确认；成功后返回岗位列表并自动刷新。

## 4. 岗位信息卡片整理

`JobListCard` 重排并高亮关键信息：

- 投递人数：右侧高亮胶囊（人数加粗 + 图标），点击进入该岗位求职者 Tab；
  缺少统计时显示「—」且不可点击，不伪造为 0。
- 发布日期：底部「发布于 …」高亮芯片（优先 `publishTime` 完整时间，
  其次 `date` 短日期，都没有时显示灰色占位）；超长省略不溢出。
- 移除无数据来源的「看过/感兴趣」占位统计。
- 状态按钮上移到标题行右侧，薪资/部门城市/标签纵向排布。
