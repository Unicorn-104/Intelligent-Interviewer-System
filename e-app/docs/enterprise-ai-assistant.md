# 企业端 AI 招聘助手

## 界面与边界

- 消息页以可拖动、贴边吸附的机器人悬浮球取代原来的“全部 / AI Agent”分栏。普通会话、通知、已读和候选人聊天逻辑保持原样。
- 独立助手页面提供 Markdown 回答、停止回答、复制、新对话、历史加载和确认删除。
- 打开助手只读取最近会话；点击新对话只重置本地页面。第一次明确发送时才创建会话。
- 历史记录来自数据库，不使用演示回答。建议问题只预填，不自动发送。
- 请求超时禁止自动重发：按 requestId 查回原回答，人工核对后才允许恢复输入。离开页面或应用进入后台关闭流式连接，后端仍可完成已接受的任务；恢复时订阅同一回答，不重复提交问题。

## 服务接口

统一前缀 `/enterprise/assistant`，必须登录并拥有有效企业绑定。用户和企业身份由后端认证及绑定关系解析，不接受客户端指定。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | /sessions | 历史分页 / 创建会话 |
| GET | /sessions/{id}/messages | 消息游标分页 |
| POST | /sessions/{id}/runs | 以24位十六进制requestId提交问题 |
| GET | /sessions/{id}/requests/{requestId} | 核对不确定请求 |
| GET | /runs/{id} | 手动核对回答状态 |
| GET | /runs/{id}/events | SSE实时输出与断线后原任务恢复 |
| POST | /runs/{id}/cancel | 停止并保留已有文本 |
| DELETE | /sessions/{id} | 删除本人、本企业的已结束会话 |

单条输入4000字符、回答12000字符。短请求提交后通过带认证的SSE连接持续接收回答，不再按1.2秒轮询。后端最多每60毫秒合并推送最新片段，8秒无文本时发送心跳，关闭代理缓存；首段抵达即可展示。恢复连接只重新订阅已有任务，不会重复生成。服务端每账号一个活动任务，有界线程池；最终或中断文本落库。模型只复用现有 AgentModelClient 的服务端配置，不向客户端下发密钥。

## 数据与权限

本功能不执行 DDL、不修改现有API或求职者Agent。复用现有通用表：

- t_ai_chat_session：acs_status=7保留为企业助手命名空间，acs_user_id绑定当前账号。
- t_ai_chat_message：role=0，intent=enterprise:<companyId>的标记绑定企业；role=1为用户问题，role=2为回答。
- 用户问题intent=q:<requestId>，回答intent=r:<questionId>:<state>。R生成中，C完成，F失败，X主动停止。
- 所有会话/回答入口（含流式连接）均校验账号与企业标记，连接期间定期核验企业绑定；最多32个流式连接，同一回答的新连接替换旧连接。求职者的t_capp_ai_*会话、简历和投递工具完全独立。
- 回答期间的增量缓存在当前进程内，结束时持久化；重启后仍为R的任务超过150秒转F，不自动重跑或计费。
- 仅有两个只读工具：本企业岗位搜索（最多15条）和本企业岗位JD查询。不检索候选人隐私，不发送IM、不发布岗位、不安排面试、不执行审批。
- 后端需要管理员已有的有效模型供应商配置；未配置时明确报错，绝不以假回答兜底。返回建议仍需人工核实。

## 验证与验收

定向测试使用合成H2数据和模型桩，不连接生产数据库，不消耗真实模型额度。覆盖企业隔离、请求幂等、取消、游标分页、只读工具、悬浮吸附、历史、新对话、超时核对、320dp、大字号及原IM回归。流式专项覆盖首段先于生成完成抵达、中文UTF-8分包、CRLF/多行SSE、心跳、认证失败、取消收尾、后台恢复及气泡逐段增长。

目标环境仍需用授权企业测试账号人工验收：模型配置、真实生成、历史恢复、停止回答、后台切回、普通IM不受影响。测试桩通过不等于真实模型线上验收。
