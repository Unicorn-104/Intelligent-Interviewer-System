# 若依管理员端权限基线
## 1. 文档定位

本文档以当前项目的 Vue 3 + Vue Router + Pinia 前端为依据，按企业级若依项目交付标准整理管理员端的：

- 路由权限
- 菜单权限
- 角色权限
- 按钮权限
- 数据权限
- 后端接口鉴权
- 权限变更、审计和验收标准

本文不纳入 Mock 数据。当前仓库未包含真实后端源码，因此后端部分定义为必须交付的接口、数据表和鉴权契约，不能视为现有后端已经实现。

## 2. 权限模型

权限链路必须保持以下关系：

`用户 -> 角色 -> 菜单/按钮权限 -> 路由/页面/API`

数据范围独立于菜单权限：

`用户 -> 角色 -> 数据范围 -> 租户/部门/资源过滤`

前端负责菜单展示、路由注册和按钮隐藏；后端负责最终鉴权、数据范围和资源归属校验。

## 3. 前端路由基线

### 3.1 公共路由

| 路径 | 页面 | 权限要求 |
|---|---|---|
| `/login` | 登录 | 匿名访问 |
| `/register` | 注册 | 匿名访问，是否开放由后端配置 |
| `/401` | 无权限 | 登录后可访问 |
| `/:pathMatch(.*)*` | 404 | 登录状态无关 |
| `/index` | 首页 | 登录后可访问 |
| `/lock` | 锁屏 | 登录后可访问 |
| `/user/profile/:activeTab?` | 个人中心 | 登录后可访问 |

### 3.2 隐藏业务路由

| 路径 | 页面 | 最低权限 |
|---|---|---|
| `/system/user-auth/role/:userId` | 用户角色授权 | `system:user:edit` |
| `/system/role-auth/user/:roleId` | 角色用户授权 | `system:role:edit` |
| `/system/dict-data/index/:dictId` | 字典数据 | `system:dict:list` |
| `/monitor/job-log/index/:jobId` | 调度日志 | `monitor:job:list` |
| `/tool/gen-edit/index/:tableId` | 生成配置编辑 | `tool:gen:edit` |

### 3.4 路由交付规则

1. 动态路由由后端按用户权限返回，前端通过组件白名单加载。
2. 每个页面路由必须有唯一 `name`、稳定 `path`、明确 `component` 和 `meta.title`。
3. 路由权限只用于页面访问控制，不能代替 API 鉴权。
4. 隐藏路由必须配置明确的 `permissions` 或 `roles`。
5. 无权限访问统一跳转 `/401`，不能返回空白页或无限重定向。
6. 角色、菜单或用户状态变化后，前端必须重新获取用户信息和动态路由。
7. 退出登录后必须清理 Token、用户权限、动态路由、标签页和缓存。
8. 路由参数必须由后端再次校验资源归属，不能只依赖前端正则。

## 4. 菜单权限基线

### 4.1 菜单类型

| 类型 | 说明 | 必填字段 |
|---|---|---|
| `M` | 目录 | `menuName`、`parentId`、`orderNum`、`icon`、`visible`、`status` |
| `C` | 页面菜单 | `path`、`component`、`routeName`、`perms`、`visible`、`status` |
| `F` | 按钮权限 | `parentId`、`menuName`、`perms`、`status` |
| `L` | 外链/iframe | `path`、`link`、协议和域名白名单 |

### 4.2 菜单字段约束

- `menuId` 使用数据库主键；前端不自行生成权限 ID。
- `parentId` 必须存在，禁止形成环路。
- `routeName` 全局唯一。
- `path` 在同一父节点下唯一。
- `component` 只能引用前端已登记的组件路径。
- `perms` 使用 `domain:resource:action` 格式，按钮权限不得为空。
- `visible` 控制菜单显示，`status` 控制菜单是否可用，二者不能混用。
- 删除目录前必须检查子菜单、角色关联和路由引用。
- 禁止将用户输入直接作为脚本、任意模块或不受控外链执行。

### 4.3 菜单层级建议

建议一级目录按当前项目业务边界划分为：租户、会员、系统、AI、内容、广告、消息、业务、监控、工具。页面菜单挂在业务目录下，按钮权限挂在页面菜单下。

页面菜单权限建议使用 `xxx:xxx:list`，按钮使用 `add`、`edit`、`remove`、`export`、`import`、`audit`、`run`、`query` 等动作。

## 5. 角色权限基线

### 5.1 交付角色

| 角色 | `roleKey` | 默认职责 | 默认原则 |
|---|---|---|---|
| 超级管理员 | `admin` | 平台最高管理 | 全部权限，受审计和二次确认约束 |
| 平台管理员 | `platform_admin` | 用户、角色、菜单、租户、系统配置 | 可管理平台，不默认拥有业务审批 |
| 运营人员 | `operator` | 内容、广告、会员、消息和日常业务 | 允许业务维护，禁止权限配置 |
| 技术支持 | `tech` | AI 配置、监控、任务和技术工具 | 禁止修改业务归属和财务数据 |
| 财务人员 | `finance` | 租户套餐、账单和财务相关数据 | 只读或受控维护非财务模块 |
| 审核人员 | `auditor` | 企业、岗位、内容和风险审核 | 只授予审核及必要查询权限 |
| 只读人员 | `viewer` | 报表和详情查看 | 禁止写入、删除、导出和授权 |

角色名称和角色编码必须以后端数据为准，不能在前端硬编码成鉴权依据。

### 5.2 角色授权规则

1. 角色状态为停用时，所有业务接口立即拒绝或在短时间内失效。
2. 普通角色不能新增、修改、停用或删除 `admin`。
3. 角色不能授予操作者自身没有的权限，除非操作者是受控超级管理员。
4. 角色授权提交时，后端必须校验菜单 ID、租户边界和操作者权限。
5. 菜单权限、按钮权限、数据范围分别保存并分别校验。
6. 角色变更必须记录操作者、目标角色、变更前权限、变更后权限和时间。
7. 删除角色前必须检查用户绑定关系；有绑定用户时禁止直接删除。

## 7. 后端数据模型交付要求

至少需要以下表或等价模型：

| 模型 | 核心字段 |
|---|---|
| 用户 | `user_id`、`user_name`、`status`、`tenant_id`、`dept_id` |
| 角色 | `role_id`、`role_name`、`role_key`、`status`、`data_scope` |
| 菜单 | `menu_id`、`parent_id`、`menu_type`、`path`、`component`、`perms`、`visible`、`status` |
| 用户角色 | `user_id`、`role_id` |
| 角色菜单 | `role_id`、`menu_id` |
| 角色部门 | `role_id`、`dept_id` |
| 权限变更日志 | 操作者、目标对象、变更前后快照、IP、时间、结果 |

菜单、角色和关联表必须有唯一约束、外键或等价一致性校验，并支持软删除或审计留痕。

## 8. 后端接口鉴权契约

### 8.1 认证接口

| 接口 | 要求 |
|---|---|
| `POST /auth/login` | 校验账号、密码、验证码、账号状态、租户状态，签发短期 Access Token |
| `GET /me` | 返回用户、角色编码、权限字符、数据范围版本和密码状态 |
| `GET /getRouters` | 只返回当前用户可访问的目录、页面和路由元数据 |
| `POST /auth/logout` | 使当前 Token 失效或进入吊销列表 |
| `POST /auth/unlock` | 校验当前用户身份和解锁密码 |

### 8.2 业务接口

每个写接口、导出接口、审核接口、执行接口、授权接口都必须具备：

- 明确的权限字符映射；
- 认证失败返回 401，权限不足返回 403；
- 资源 ID、租户 ID、部门范围的服务端校验；
- 参数校验、幂等控制和审计日志；
- 不信任前端传入的权限、角色、部门和数据范围字段。

### 8.3 权限缓存

权限缓存必须包含用户身份、角色状态、权限版本和租户信息。角色、菜单、用户角色关系变更后必须刷新缓存或递增权限版本，使旧权限在约定时间内失效。

## 9. 数据权限基线

建议支持若依常见数据范围：

| 类型 | 含义 |
|---|---|
| `1` | 全部数据 |
| `2` | 自定义数据 |
| `3` | 本部门数据 |
| `4` | 本部门及以下数据 |
| `5` | 仅本人数据 |

数据权限必须在查询、详情、修改、删除、导出和下载接口统一执行。不能只在列表 SQL 过滤，详情接口和文件下载接口也必须校验数据范围。

## 10. 审计与安全基线

必须记录：登录、退出、登录失败、角色授权、菜单变更、用户状态变更、密码重置、导出、删除、审核、执行、强制下线、清缓存和权限拒绝。

高风险操作要求：

- 删除、授权、停用、清缓存、强制下线二次确认；
- 导出和下载记录操作者、筛选条件、数据量和文件标识；
- 审计日志禁止普通业务角色修改或删除；
- Token、密码、密钥和隐私数据禁止写入前端日志和普通操作日志；
- 生产环境使用 HTTPS、HttpOnly/SameSite Cookie 或等价安全 Token 方案。

## 11. 企业交付验收标准

### 路由验收

- 未登录访问业务路由跳转登录。
- 无权限用户手工输入 URL 返回 401 页面。
- 动态路由只加载白名单组件。
- 角色变更后旧页面和旧标签页不能继续调用受保护接口。

### 菜单验收

- 菜单树、侧边栏、面包屑和后端权限数据一致。
- 停用菜单不返回、不注册、不显示。
- 删除菜单前阻止存在子节点或角色关联。
- 外链和 iframe 通过协议、域名白名单校验。

### 角色验收

- 角色增删改、启停、授权均有后端鉴权。
- 普通角色无法给自己追加更高权限。
- 角色数据范围对列表、详情、导出、下载全部生效。
- 权限变更有审计记录并触发缓存失效。

### 按钮和接口验收

- 每个 `v-hasPermi` 都能在菜单权限表找到。
- 每个写入、删除、导出、审核、执行接口都有后端权限校验。
- 删除按钮、导出按钮和隐藏页面不能通过直接请求绕过。
- 权限不足统一返回 403，前端统一处理并提示。

## 12. 交付物清单

1. `管理员端权限基线-企业交付版.md`。
2. 菜单初始化 SQL 或菜单导入 JSON。
3. 角色初始化 SQL 及角色-菜单-部门关联数据。
4. 接口权限映射表：API、HTTP 方法、权限字符、数据范围、审计类型。
5. 权限验收用例和普通角色测试账号。
6. 权限变更、缓存刷新和审计日志说明。

## 13. 当前项目结论

前端已具备动态路由、角色权限指令和按钮权限使用基础；当前需要以后端正式实现作为交付闭环：菜单与角色关系持久化、接口级鉴权、数据范围、租户隔离、权限缓存和审计日志。

在真实后端交付前，不能宣称管理员端权限已经达到企业生产标准。
