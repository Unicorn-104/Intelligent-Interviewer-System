# 用户 PC 端消息图片、链接与表情

## 现有接口

- `GET /system/im/sessions/{sessionId}/messages`：读取当前用户参与的会话消息。
- `POST /common/upload`：以 multipart 的 `file` 字段上传图片或文件。
- `POST /system/im/messages`：向现有 `sessionId` 或新会话的 `peerId` 发送消息。

图片使用 `type=2`，文件使用 `type=3`；附件发送时优先读取上传结果中的 `fileName`，仅保存 `/profile/...` 形式的后端路径。不能把前端 `/dev-api`、`/prod-api` 或用户 PC 端域名写进发送载荷，避免后端路径校验失败。

上传时使用随机 ASCII 文件名，消息中的显示名仍使用用户选中的原始文件名，避免原文件名包含空格、中文、`#`、`?` 等字符影响后端存取。上传响应兼容根对象和 `data` 包装；`fileName` 无效时尝试有效的 `url`，不将无效上传结果写入聊天记录。

## 接收兼容

- 消息 `type` 兼容数字和数字字符串。
- 企业端将图片作为 `type=3` 文件发送时，按附件路径中的 JPG、JPEG、PNG、GIF、BMP、WebP 后缀识别为图片。
- 历史 `/profile/...`、旧域名或 localhost 下的 `/profile/...`、带 `/dev-api` 或 `/prod-api` 的 profile 地址统一映射到当前 API 前缀。
- 其他 HTTP(S) 外链保留原始地址，不向外部站点转发当前用户的 Authorization。
- 图片点击后在站内预览，支持关闭按钮和 Escape；不会修改 body 的滚动样式。
- 加载失败提供重新加载入口，不将网络错误永久判定为文件已删除。

以上路径兼容以多个端共用同一后端文件存储为前提；如果原文件仅保存在旧机器或已被删除，需要同步存储或重新发送，前端不能恢复丢失的文件。

`No static resource upload/...` 表示收到请求的后端找不到相应文件，并不代表没有会话记录。仅共享数据库不会自动同步各机器的上传目录；联调时应让两端连接同一后端实例，或者由运维配置共享文件存储。下载失败时前端展示中文原因，不把服务器原始路径和异常堆栈直接显示给用户。

## 链接和表情

- 文本中的完整 HTTP(S) 面试、笔试及其他链接在新标签页打开，保留查询参数，链接使用 `noopener noreferrer`。
- 普通文本与 HTML 字样仍作为文本展示，不使用 `v-html` 执行聊天内容。
- 工具栏新增表情面板，表情插入光标处或替换选中文字，点击发送后沿用 `type=1` 的真实消息接口。
- 表情计入现有 1000 字符限制；服务端和数据库连接需要支持 Unicode 补充字符（通常为 utf8mb4）。

## 验证

执行 `npm run test:unit`，覆盖跨环境路径、消息类型、链接参数与标点、安全协议、表情插入及长度限制。

双端联调需使用实际 HR 和求职者账号：HR 分别发送图片、图片文件、PDF 和带参数的面试链接；求职者确认图片展示/预览、文件打开、链接访问，并发送表情后在 HR 端确认收到。单元测试与隔离浏览器测试不替代真实双端联调。
