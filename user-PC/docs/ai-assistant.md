# PC 求职 AI 助手

## 入口与交互

- 消息通知页面右下角“AI 求职助手”；职位详情进入的 `/job-assistant?id=岗位ID` 共用同一真实助手，不再使用模拟岗位或预设回答。
- 选择简历：读取本人“我的简历”，仅影响本次 AI 上下文，不修改默认简历。
- 选择岗位：与 App 一致，选择本人已投递岗位，自动关联该次投递使用的简历。与当前有效简历列表核对，缺少关联简历或简历已删除、停用的记录不可选；选择时再次校验，不擅自换成其他简历。
- 岗位推荐与简历分析要求先选简历；面试准备要求先选已投递岗位；写作润色与自由聊天不要求资料。快捷功能准备问题后，由用户确认发送。
- 回复以 Vue 文本插值展示，保留换行，清理常见 Markdown 外观标记，不使用 Markdown 库、`v-html` 或任意 HTML 渲染。岗位卡片独立展示，可进入真实职位详情。
- 不自动投递岗位、不自动保存修改后的简历，也不生成虚假岗位或匹配分数。

## 真实接口

| 功能 | 接口 |
| --- | --- |
| 个人简历 | `GET /agent/v1/resumes` |
| 本人投递分页 | `GET /agent/v1/applications?page=1&size=20` |
| 投递上下文恢复 | `GET /agent/v1/applications/{id}` |
| 会话分页 / 新建 | `GET /app/ai/sessions?before=...` / `POST /app/ai/sessions` |
| 消息分页 | `GET /app/ai/sessions/{id}/messages?before=...` |
| 重命名 / 置顶 | `POST /app/ai/sessions/{id}/rename` / `POST /app/ai/sessions/{id}/pin` |
| 删除会话及消息 | `DELETE /app/ai/sessions/{id}`（用户二次确认） |
| 启动任务 | `POST /app/ai/sessions/{id}/runs` |
| 任务状态 / 停止 | `GET /app/ai/runs/{id}` / `POST /app/ai/runs/{id}/cancel` |
| 流式回复 | `GET /app/ai/runs/{id}/events?after=事件游标` |

启动任务携带 `requestId`、`content`、`resumeId`、`applicationId`、`action`。action 使用后端已有的 `chat`、`job_recommendation`、`resume_analysis`、`interview_preparation`、`writing_polish`。面试上下文绑定投递简历，简历分析与推荐不混入其他投递。服务端按登录用户校验会话、简历和投递归属。

## 历史、流式回复与异常

- 历史记录使用后端持久化，PC 与 App 共用；支持标题搜索、分页、置顶、重命名、确认删除，搜索范围为已加载会话，提供加载更多入口。
- 消息支持加载更早记录。新消息在用户位于底部时跟随；用户上翻时不抢滚动，点击“回到最新消息”恢复跟随。
- 从创建任务起防止重复点击；任务创建重试保留同问题的 requestId。按事件 ID 断线续传与去重，重连失败保留任务并提供“恢复回答”和“停止”。
- 页面关闭或路由卸载只中断浏览器读取，不误取消服务端任务；重开会话可恢复 activeRunId。停止生成必须调用服务端取消接口。
- 模型连接及流式无进展等待最多45秒，持续生成时单次调用最多180秒；整轮任务最多240秒，失联任务在270秒后回收。流式接收内容会刷新空闲计时，避免原先固定90秒截断仍在生成的回答。超时不自动重发模型请求，用户确认后再提问。
- 普通聊天输出预算1536 tokens，岗位推荐和写作润色2048 tokens，简历分析和面试准备3072 tokens；先给结论与关键依据，避免简单匹配问题生成长篇重复内容。超过输出预算仍明确提示未完成，不冒充成功。
- 模型小文本碎片按500毫秒或512字符合并写入事件表，不再逐碎片同步读写远程数据库；完成及异常收尾时刷新剩余片段。模型返回合法结束原因后立即结束本轮读取，不等待连接关闭；结束片段未携带usage时按字符保守估算，不作为计费数据。
- 收到正文时显示“正在生成回答”；收到done立即收尾，不等待HTTP断开。同时每5秒只读核对任务状态，结束事件丢失或连接保持打开时，依据后端状态恢复已保存回答或显示失败并解锁。读取的状态轮询不创建新任务，停止和卸载会清理连接及定时器。
- 历史记录、选择列表、回答失败分别提示，不用模拟数据替代失败。没有模型配置、数据表或相关权限时必须先完善服务器环境。
- 历史对话仅恢复仍可访问的有效简历及投递；原简历已失效时保留历史消息，清除失效上下文并提示重新选择。所有携带简历的请求（包括自由聊天）在调用模型前由后端核验并提供结构化职业信息，不恢复已删除简历、不放宽归属权限。
- 助手不修改 body/html 的滚动属性；所有样式以 `pc-ai-` 前缀和 Vue scoped 隔离。

## 验证

定向单测：`node --test test/agentAi.test.js`；回归：`npm run test:unit`；构建：`npm run build:prod`。

真实验收需登录有效求职者账户及可用的 AI 模型配置：分别选择两份简历分析、选择已投递岗位准备面试、查看岗位卡片、停止并恢复对话、翻页和操作历史，再验证路由返回与滚动。隔离接口的浏览器交互测试不代表真实模型或服务器完整验收。
