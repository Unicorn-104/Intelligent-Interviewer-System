## 二、分工原则

- C-PC 与 C-APP 业务范围一致，但由何方圆和马志荣分别实现。
- E-PC 与 E-APP 业务范围一致，但由姚林旭和张祥分别实现。
- 五端共用后端接口、认证机制和数据库，不复制五套后端。
- 端负责人负责本端页面、路由、请求封装、状态处理、权限表现和端侧测试。
- 公共接口、错误码和权限码由李洪萍维护契约，任何人不得私自改变公共字段。

## 三、五端任务

### 1. 用户 PC 端（C-PC）——何方圆

- 初始化若依 Vue3 工程、登录注册、路由、权限和候选人布局。
- 个人资料、账号安全、隐私和通知设置。
- 简历上传、解析结果、教育/工作/项目/技能、预览和导出。
- 岗位搜索、筛选、热门标签、岗位详情、收藏。
- 人岗匹配、投递、撤回、投递记录和面试状态。
- 面试邀约、预约、入口、阶段信息、通知和反馈。
- AI 求职助手页面，AI 结果明确标注为辅助建议。

### 2. 用户 App（C-APP）——马志荣

- 初始化 Flutter Android/iOS 工程、路由、Token、网络层和底部导航。
- 登录注册、个人资料、隐私、通知和账号安全。
- 手机文件/相机上传简历、解析结果、简历编辑和预览。
- 岗位搜索、筛选、详情、收藏、匹配、投递和投递记录。
- 面试预约、面试入口、阶段状态、通知、AI 求职助手和反馈。
- 适配文件、相机、麦克风、推送、弱网和上传失败场景。

### 3. 企业 PC 端（E-PC）——姚林旭

- 初始化若依 Vue3 企业布局、企业/部门/岗位权限和数据权限。
- 企业资料、部门、HR、面试官账号与授权。
- 岗位发布/编辑/下线、JD 解析、候选人筛选和人岗匹配。
- 多阶段面试流程模板、版本、阶段、顺序、时长、并行和条件分支。
- 预约调度、面试官日历、评分卡、多人评分、Offer 和背景调查。
- 招聘漏斗、阶段转化和招聘数据看板。

### 4. 企业 App（E-APP）——张祥

- 初始化 Flutter Android/iOS 工程、企业登录、组织权限和移动消息。
- 企业/部门概览、岗位查看、快速发布/下线。
- 候选人搜索、简历查看、收藏和标签。
- 面试邀约、日历、改期/取消、面试提醒和移动面试入口。
- 评分卡、多人评分提交、流程阶段、Offer 审批和待办。
- 适配移动端权限、推送、弱网和关键操作二次确认。

### 5. 系统管理员端（A-PC）——田清宇

- 初始化若依 Vue3 管理后台、管理员登录、角色/菜单/按钮权限。
- 用户管理、企业审核、HR/面试官审核、启停用和实名状态。
- 角色权限、数据范围、字典、通知模板和安全策略。
- Agent 启停用、Prompt 版本、模型 Provider、重试、降级和人工接管。
- 登录/操作/接口审计日志、异常告警、服务健康和数据库/Redis/存储/AI 服务状态。

## 五、协作与完成标准

1. 每个端使用独立分支：`feature/c-pc-*`、`feature/c-app-*`、`feature/e-pc-*`、`feature/e-app-*`、`feature/a-pc-*`。
2. 一个 PR 只解决一个功能或缺陷；必须附接口说明、截图/录屏和测试结果。
3. 功能开发顺序固定为：接口确认 → Mock 页面 → 接口联调 → 异常状态 → 自测 → PR。
4. 页面必须处理加载中、空数据、错误、无权限和重复提交状态。
5. 通过本端类型检查、Lint、构建和最小操作测试，并在测试环境验证后才能合并。
6. 不得提交密码、Token、模型密钥和个人敏感信息。

