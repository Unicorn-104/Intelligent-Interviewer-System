# 企业端按招聘阶段排期

入口：候选人详情 → 邀请面试。日期和时间统一使用 UTC+8。

## 行为

- 加载岗位真实招聘流程及候选人已有阶段预约。每个阶段独立选择面试官、日期、开始时间和时长，确认时统一发送未安排阶段。
- 任一阶段发生冲突时，整个批次不保存。已安排阶段通过原预约编辑，不重复创建预约。
- 周日历统计当前企业的面试安排，排除已取消预约；日期右上角显示数量，0–5 场为绿色、6–10 场为警示色、11 场及以上为红色。跨日面试在涉及的每一天计数。
- 七天日期格展示数量，选择日期后展示当天时间轴；面试块高度按实际时长绘制，同时安排的面试分列。
- 点击面试块编辑日期、时间、面试官和时长；长按上下移动，拖动上边界调整开始时间（结束时间不变），拖动下边界调整结束时间（开始时间不变），按 15 分钟吸附。拖动时实时预览，松手才提交；取消触摸或拖动中到达面试开始时间则还原，不提交。日期也可在编辑弹窗中修改。
- 已开始、已完成和已取消的面试仅可查看。
- 现有的单阶段接口继续可用。岗位尚未配置流程时使用原单阶段邀约；流程加载失败时阻止提交并提示重试。

## 接口增量

- `GET /system/enterprise/jobs/{posId}/workflow`：阶段增加 `stageId`。
- `GET /enterprise/interview/candidate-plan?candidateId=...&positionId=...`：查询候选人在该岗位的已有预约，不受当前日历周限制。
- `POST /enterprise/interview/invite/stages`：`{candidateId, positionId, stages:[{stageId, interviewerId, startTime, durationMin}]}`。返回对应预约数组，整批事务提交。
- `POST /enterprise/interview/invite`：兼容原参数，支持可选 `stageId`。
- `PUT /enterprise/interview/{appointmentId}/reschedule`：保留 `newStartTime`，增加可选 `durationMin`、`interviewerId`；不传时保留原值。兼容原响应字段，补充预约字段。
- 面试列表和详情增加 `stageId`、`stageName`、`stageType`、`stageOrder`。周查询使用半开区间，并包含与区间重叠的跨日面试。

## 数据库与校验

仅执行 `e-app/new.sql` 末尾“预约记录关联招聘流程阶段及排期快照”追加段；不要重复执行整个历史文件。

新增预约表四个可空字段：`apt_stage_id`、`apt_stage_name`、`apt_stage_type`、`apt_stage_order`，以及阶段外键和索引。脚本支持重复执行，保留旧记录；不推测旧预约的阶段归属。名称、方式和顺序使用邀约时快照，流程修改后仍可查看历史信息。回滚步骤已在 SQL 追加段注释中给出，先回滚应用并导出阶段信息再回滚结构。

创建和改期在事务中按候选人、面试官顺序加锁。服务端校验企业归属、投递关系、阶段归属、未来时间、1–1440 分钟时长、候选人/面试官占用与阶段先后顺序；首尾相接的时段允许安排。改期排除预约自身占用，验证成功后才释放旧时段；冲突或写入失败时回滚。

## 验证与验收

自动测试包含真实 Mapper 与事务代理的后端集成测试、Flutter 邀约与日历组件测试。后端集成测试在独立 H2 数据库运行，不写入业务数据。

人工验收：选择实际投递候选人，逐阶段排期并确认；重新进入检查保存结果；在日历中点击、长按移动、拖动底边，验证成功持久化和冲突时原安排保留。人工验收须在 Pixel_10a 上完成，不以单元测试代替。
