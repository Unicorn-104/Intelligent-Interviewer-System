# 用户 PC 全站悬浮 AI 助手

## 入口与行为

- 在应用根节点挂载唯一助手，首页、岗位、消息、简历、基础资料、登录注册以及独立公开页面共用入口；移除消息页和旧独立助手页的重复实例。
- 点击悬浮按钮展开/收起；鼠标或触屏拖动按钮、对话框标题栏可自由移动。方向键移动 20px，Shift + 方向键移动 5px。标题栏内的历史、新建、关闭按钮不触发拖动。
- 超过 6px 才识别为拖动，拖动结束不误触展开。指针捕获保证快速拖动连续，释放、取消及组件销毁时清理捕获与监听。
- 窗口始终限制在可见区域，缩放及调整浏览器大小后自动校正；当前标签页 sessionStorage 只记录按钮和窗口的归一化坐标，刷新可恢复。存储不可用或损坏时采用默认位置，不保存聊天或简历数据。
- 切换站内页面不卸载助手，保留正在进行的回答、当前对话、未发送问题、简历与岗位选择及窗口位置。关闭窗口不取消后台任务；切换登录身份时重新挂载，清理前一个账号的内存状态和流连接。
- 岗位助手与面试准备页面引导使用同一个悬浮窗口；进入相应页面时展开，面试准备设置对应功能，不伪造 AI 结果。

## 鉴权与接口

复用已有 AI 会话、历史、简历、投递和 SSE 接口，不增加后端接口、数据库字段或依赖。默认挂载不读取 AI 私人数据；游客主动打开时才提示登录/注册，登录跳转使用 Vue Router，兼容不经过求职者 shell 的公开页面。账号变化后不复用旧会话状态。

## 选择列表竞态修复

展开或跨页重新展开助手、切换选择类型、返回聊天时，统一调用选择流程失效逻辑，递增请求代次并清除旧加载状态和待执行快捷动作。列表成功、错误和 finally 回调同时检查请求代次与选择类型，旧网络响应即使返回也不能修改新列表或解除新请求的加载状态。采用逻辑取消，不依赖底层网络是否能及时中止。

回归测试用可控的延迟响应覆盖：简历请求未结束时跨页展开后选择岗位、直接切换列表、迟到成功、迟到错误和关闭后回填。新岗位请求无需等待旧请求；对应回归在修复前失败，修复后通过。
