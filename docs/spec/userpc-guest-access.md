# 用户 PC 游客浏览

- 打开站点根路径（生产环境 `/user/`）进入首页，不强制跳到登录页。
- 游客可以访问 `/index`、`/jobs`、`/job-detail?id=...`，搜索、筛选和查看真实发布的岗位。
- 右上角显示登录、注册入口；登录和注册页提供“先逛逛”返回首页。
- 投递、收藏、查看投递、消息、简历、AI 助手和个人资料仍需登录。提示中可选择登录、注册，关闭提示继续浏览。
- 登录或注册完成后的登录流程保留原目标的参数及锚点；仅接受站内求职页面地址，不接受外部跳转。
- 游客首页不读取简历、通知、投递、面试安排、未读数或历史本地收藏，不把未登录显示成个人数据为零。

## 接口与权限

仅岗位列表、岗位分类、岗位筛选选项、岗位详情四个 GET 方法通过 `@Anonymous` 开放匿名读取。
访问者身份由后端认证上下文决定，不接受查询参数中的 `userId`。匿名请求不使用简历、不返回个人匹配分或投递记录 ID，也不返回原始岗位 JSON、企业扩展元数据；公开职责和要求保留。携带 `resumeId` 时拒绝推荐查询。
登录用户沿用原有本人简历校验和推荐逻辑。简历、投递、聊天及文件接口没有开放匿名权限；前端提示不能代替后端鉴权。

## 部署与验收

- 前端执行 `npm run test:unit`、`npm run build:prod`，部署 `dist` 至 `/user/`，沿用已有 SPA history 回退配置。
- 后端需要重新构建并重启，只有更新前端不能开放匿名岗位接口。无数据库迁移、无新增依赖或凭据配置。
- 验收应使用无登录 Cookie 的浏览器：直接打开首页、刷新详情、搜索筛选、点击投递和收藏、关闭提示、登录后回跳；游客浏览期间不应出现个人接口请求或过期会话弹窗。
- 回滚时恢复本次前后端变更，私有操作的服务端认证要求保持不变，不删除业务数据。
