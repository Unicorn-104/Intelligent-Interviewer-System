SECTION 01

结论摘要

三条结论，按优先级排列。

一、注册功能不重写，只做入口分流。 origin/dev 已有完整的企业自助注册（POST /register/enterprise），建企业、建账号、绑企业 ID、授 biz_1、置双待审，一步不缺。现有 /register 是若依原生个人注册，保留但其定位必须收窄，否则企业用户走错门会得到「无企业绑定」的空账号。
二、Agent 不完整的根因不是功能少，是结构分裂。 三端各有一套模型调用与工具实现：求职者端有记忆与续传、企业端有工具接口抽象但只有两个只读工具、管理端有完整写闭环却把逻辑写在控制器里。再加一套就等于第四份技术债。
三、先收拢结构，再补功能。 抽出 AgentTool 接口与按端注册的工具包，把写操作统一走「草稿—确认—落库—撤销」，并补一条工具调用审计。结构到位后，企业端与求职者端补写能力只需注册工具，不再重写编排。

SECTION 04

目标架构：一内核 + 按端工具包

四层职责清晰：编排只管流程，工具只管能力，审批只管写，存储只管数据。

核心抽象

// 1) 工具接口：只描述能力，不知道端
public interface AgentTool {
    String name();
    ObjectNode definition(ObjectMapper json);            // JSON Schema
    ToolResult execute(ToolContext ctx, JsonNode args);   // ctx 携带端、用户、companyId
}

// 2) 工具包：按端组装，构造时注册
public interface AgentToolPackage {
    String scope();                       // admin | enterprise | seeker | exam
    ArrayNode definitions(ObjectMapper json);
    AgentTool find(String name);
}

// 3) 审批：写工具只产草稿
public interface AgentActionStore {
    String save(PendingAction action);    // 返回 pendingId
    PendingAction take(String id);        // 一次性消费，过期返回 null
    void discard(String id);
}
抽象层不复用企业端现成类名，是为了避免「企业端 = 全局」的语义误导；实现上可直接复用其接口形态。

注意：apply 的 body 字段名是 id，不是 pendingId。前端已按此实现，联调时按错参数会返回「缺少待确认编号」。

SSE 事件协议

eventdata前端处理
tool纯文本进度，如「正在查询业务数据…」追加到气泡尾部状态
answer{"text":"…"}渲染正文，触发打字机或直接替换
pending卡片数组：id / kind / title / summary渲染确认卡片，绑定 apply / discard
[DONE]data: [DONE]关闭连接、复位 loading

普通问答仍走原生流式（仅 data: 行），只有命中题库意图时才切换到带事件的非流式分支。这是为了在有工具的场景下保证事件顺序可控。

工具名使用 snake_case 动宾短语；description 必须写清「是否落库」，这是模型不乱承诺的关键。

模型输出兼容

实测中遇到两类模型侧异常，均需在编排层兜底，不应指望模型守规矩：

  • 文本化工具调用：模型把调用写成 invoke name="x" 标记而非标准 tool_calls。处理：正则提取工具名与参数，执行后把结果以 user 消息回灌。
  • 参数形态漂移：items 缺失、被序列化成字符串、或单题字段平铺在顶层。处理：三种形态都归一成数组再校验。

禁止的做法：为文本化调用伪造 role:"tool" 消息。缺少对应 tool_call_id 时服务端会直接返回 HTTP 400。

SECTION 07

关键流程：出题与撤销

出题闭环（五步）

撤销算法

撤销不是「删掉这一批」，而是「删掉这一批里还没被业务引用的」。判定集合定义如下：

-- alive：本批写入且仍存在的题
SELECT eqs_id FROM t_exam_question
WHERE eqs_id IN (批次 eqb_question_ids);

-- locked：已被考卷 / 答题引用的题
SELECT DISTINCT epq_question_id FROM t_exam_paper_question WHERE epq_question_id IN (...);
SELECT DISTINCT ean_question_id FROM t_exam_answer        WHERE ean_question_id IN (...);

-- 实际删除：alive − locked
DELETE FROM t_exam_question WHERE eqs_id IN (alive - locked);
UPDATE t_exam_question_import_batch SET eqb_status = 1 WHERE eqb_id = ?;

返回四个数：deleted、skipped、referenced、status。其中 skipped 说明题已不存在（可能被人工删过），referenced 说明被考卷占用而保留。两者都不应被视为失败。

失败与幂等

场景系统行为用户可见
重复 apply 同一 idtake() 已消费，返回 500「草稿已过期或已提交，请让助手重新生成」
超过 10 分钟未确认TTL 到期，取不到同上
重复撤销同一批次eqb_status=1 校验拦截「批次 #N 已撤销过，不能重复操作」
题目被考卷引用删除跳过，计入 referenced结果里明确给出保留数量
模型未配置 / 密钥无效AgentModelClient.resolve() 抛 503「AI 模型未配置，请先在 AI 配置中启用模型」

已知结构性风险

  • 内存态不可持久：草稿存在 ConcurrentHashMap，进程重启即失效。单实例可接受；一旦多实例部署，必须换成 Redis 或库表，否则 apply 会落到没有该草稿的节点。
  • 模型缓存不失效：activeProvider() 成功即缓存，改库中的 mpp_status 后必须重启后端才生效。
  • JdbcTemplate 不分页：题库列表走原生 SQL，PageHelper 不介入，全量渲染。数据量上去后需要补分页。

注册功能改造

两条注册路径对比

维度POST /register（现有）POST /register/enterprise（dev 已有）建议
定位若依原生，个人账号企业自助注册保留两者，明确分工
建企业不建建 t_cmp，cmp_verify_status=0不动
账号身份未设置 user_identity_type设为 2（企业）不动
企业绑定无绑 company_id + 企业管理员角色 biz_1不动
审核态直接可用企业与账号双待审，不自动登录不动
开关sys.account.registerUserselectCaptchaEnabled()两开关对齐，避免一边能注册一边被拦
结论：不重写企业注册。 它是完整实现，重写只会引入第二套绑定规则。真正缺少的是「入口不混淆」——企业用户不该看到个人注册表单。

三处改动

#改什么怎么改
R1 admin_pc/src/views/register.vue 改为双入口：默认「企业注册」指向 /register/enterprise 表单，个人注册降为次级入口；文案去掉企业相关字段
R2 后端 /register 返回文案 成功后提示「个人账号注册成功」；避免与企业的「请等待平台审核」混淆
R3 前置校验 企业注册依赖角色 biz_1 存在，缺失时明确报「系统未配置企业管理员角色」，不要静默失败

不改的部分及理由

  • 不改 EnterpriseRegisterServiceImpl：它已处理账号唯一、手机号唯一、企业名唯一、手机号正则、事务回滚，改动收益低于风险。
  • 不合并两个接口：一个建企业、一个不建企业，合并会让权限与审核逻辑纠缠。
  • 不在本期做企业邀请码：属于独立功能，与注册入口分流无依赖关系。

SECTION 10

验收清单

每条都要有可复现的输入与可核对的输出，不勾选「应该没问题」。

  • A1 只读问「题库多少题」→ 数字与库内 COUNT(*) 一致，题型分项求和等于总数
  • A2 出 3 题 → 返回 pendingId，题库条数不变
  • A3 确认落库 → inserted 等于提交数，ids 均可查到，批次表新增一行且 eqb_question_ids 与之一致
  • A4 撤销该批次 → deleted = 插入数，库回到原条数，eqb_status=1
  • A5 二次 apply 同一 id → 明确拒绝，库无变化
  • A6 撤销被考卷引用的批次 → referenced > 0，被引用题仍在
  • A7 批量改分类 → 草稿阶段库内分类不变，确认后才变
  • A8 模型返回文本化工具调用 → 仍能正确执行并给出干净答案，用户看不到标记文本
  • A9 企业注册 → 建出 t_cmp（待审）+ 账号（identity_type=2）+ biz_1 授权，且不自动登录
