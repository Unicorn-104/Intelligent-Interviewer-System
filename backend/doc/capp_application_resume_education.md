# C-App 投递简历与教育经历关联

## 问题和修复

复用同公司既有候选人档案投递新岗位时，app_resume_id 已使用所选简历，但 tal_resume_id 仍可能指向旧简历。读取人才档案的旧链路因而看不到本次简历的教育经历。

只在新增投递成功的同一事务中，将该用户、该公司人才档案的当前简历关联更新为本次有效且本人所有的简历。更新失败则投递失败并回滚。重复投递或非法简历不会更新关联。不自动重投，也不按最新简历批量覆盖历史档案。

合并基线已新增企业独立不可变简历快照；本修复保留 selectAppId 与 createForApplication，包括快照教育等结构化内容，仍在同一事务内。旧投递 app_resume_id 和既有企业快照不改写。企业已迁移到快照读取的详情继续按每条投递快照显示。

## 接口与数据

投递路径、请求字段、响应、现有流程实例创建不变，无新增表或数据迁移。updateCandidateResume SQL 同时约束 talent/user/company，使用 exists 校验简历所有人及启用状态；SQL 使用参数绑定。

## 验证与回滚

在交付分支执行 Maven 编译与相关测试，详见 PR。H2 MySQL 模式实际 Mapper 验证包括：新增投递关联与教育读取、旧记录保留、重复投递、用户/公司/停用校验、流程或快照失败的事务回滚。企业快照服务在此用 mock 验证调用；完整快照由已有专门测试覆盖。

用户已确认原业务问题解决，本次不再重复投递或修改真实数据。未在服务器部署这批代码。回滚相应提交，不删除投递和快照；回滚代码不会自动恢复运行期间合法更新的档案关联，若需恢复应单独审查具体记录。
