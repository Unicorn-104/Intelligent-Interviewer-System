# C-APP 求职 Agent：第一批交付

入口为消息中心的「AI Agent」。本批实现会话与有界工具型 Agent，对应计划阶段 1、2。

## 对话入口调整（2026-10-20）

AI Agent 以自由对话为主：进入页直接显示欢迎语、可换一组的提问建议、底部输入框与可选功能入口。简历分析、岗位推荐、面试准备和写作润色以快捷入口提供，点击后可编辑问题再发送；历史会话改为右上角入口。新对话在首次发送时才创建，不因打开页面生成空会话。普通聊天不要求选择简历，且不自动拉取或发送简历资料；即使选中了简历，也只在模型为当前业务需求调用工具时读取。仍保留每次工具调用的归属校验。

本次调整无表结构变更，无需新增 SQL 或重复执行迁移。初次部署仍使用下述四张表的迁移脚本。

入口布局后续调整：消息中心移除「全部 / AI Agent」切换，消息列表右下方提供「AI 助手」悬浮入口。点击后通过根 Navigator 弹出近全屏覆盖页，盖住底部导航；左上角关闭后恢复原消息列表和滚动位置。覆盖页保留欢迎语、提问建议、快捷功能、文本输入、历史会话与新对话，不展示尚未实现的语音或数字人按钮。此项仅客户端布局变化，无后端接口或数据库变更。

对话恢复（2026-10-21）：再次点击 AI 助手入口时，默认恢复当前账号上次打开的已保存会话；本地仅保存会话 ID，不保存聊天正文。首次没有本地记录时，使用历史列表中最新创建的会话；没有历史时显示新对话。右上角「新对话」仍显式进入空白聊天页，首次发送后再创建并记住正式会话；未发送的新对话不会覆盖上次已保存会话。恢复期间禁用发送，读取失败提供重试，避免误建新会话。此项复用现有历史、消息与流式恢复接口，无接口或数据库变更；按用户要求，本次未运行测试。

## 模块位置

对话历史列表按会话创建时间分为「今天」「最近一周」（今天以前的七个自然日）和「更早」，按现有创建顺序分页，当前会话显示浅灰圆角高亮。当前为未发送的新对话时，客户端在「今天」提供一条高亮的「新对话」本地入口，点击保留草稿；首次发送后由正式会话记录替代，不额外创建空数据库会话。已保存会话的三点菜单支持重命名，后端校验登录归属和 1～80 字标题，重命名后仍在原日期组；列表返回带时区的 ISO `createdAt`，客户端按本地日期分组。接口 `POST /app/ai/sessions/{id}/rename`，正文 `{title}`，返回 `{id,title}`。此项复用原创建时间、标题字段，无表结构变化，无新增 SQL。

- Controller：`ruoyi-admin/.../web/controller/app/AppAiController.java`
- Service / 编排 / 工具 / 模型适配：`ruoyi-system/.../service/app/ai/`
- DTO：`ruoyi-system/.../domain/app/ai/`
- Mapper：`ruoyi-system/.../mapper/app/AppAiMapper.java` 与 `resources/mapper/app/AppAiMapper.xml`
- 客户端：`c-app/lib/features/ai/{data,domain,presentation}/`

## 当前能力与边界

1. 会话列表、历史消息、游标分页和账号隔离；聊天上下文取最近 16 条未摘要消息并限制长度，另注入当前会话滚动摘要和用户确认的长期偏好，详见下方记忆说明。
2. 兼容 Chat Completions 的流式模型调用，复用后台启用的 Provider。地址必须为 HTTPS，不跟随重定向；密钥仅用于服务端请求。供应商须支持流式内容、`tools` 和 `tool_calls`。
3. 模型自主选择 `list_resumes`、`get_resume`、`search_jobs`、`get_job_detail`、`get_application_history`。后端逐次校验身份、参数、简历归属和岗位状态；无原始 SQL、URL 请求、文件读写和业务写操作工具。
4. 每次任务最多 6 轮决策、12 次模型选择的工具调用；每轮最多 4 个工具，单次模型输出最多 8192 Token，单次模型调用最多 90 秒，并共享任务 120 秒总时限。单次输出字符上限 32768、任务累计输出字符上限 65536，模型流响应字符上限 2000000（包含流式协议开销）。模型以 `finish_reason=length` 结束或触及输出字符上限时，返回 `OUTPUT_LIMIT`，客户端提示拆分问题，不把截断回答当作完整回答。上下文、累计用量另有限额；无 usage 时按字符量保守估算，不能把估算当作计费 Token。网络 I/O 异常仅在尚未输出内容时重试一次，共享总时限。
5. 工作池 4 线程、等待队列 8 个；进程内限制每账号一个任务，数据库账号记忆状态行锁将任务创建与记忆修改串行化，跨进程也检查账号活动任务。队列等待计入过期判定。超过 150 秒的遗留任务在再次查询时标记失败，释放会话。
6. 请求使用客户端随机 `requestId` 去重。同一编号同一正文和简历返回已有任务，换正文则拒绝。请求不明确失败时客户端复用编号；明确失败后用户可重新发送。消息保存与会话占用在事务内，取消和完成通过状态条件更新竞争，取消后不会补写迟到的最终回答。
7. SSE 事件持久化，支持游标重连；离开页面只断开订阅，任务继续，重新进入可恢复。停止按钮调用取消接口。部分生成内容仅属于未完成回答，成功后保存完整 assistant 消息，失败/取消不把部分结果存为成功消息。
8. 岗位卡片只来自本轮详情工具查证的真实岗位，完成时再次校验；最多显示 5 张，模型不能自行提交卡片字段。卡片是本轮查证岗位，不能视为模型最终文字逐项排序；无伪造匹配百分比。后续详情/投递仍需校验实时状态。
9. 工具载荷投影职业信息，隐藏常见邮箱、手机号、身份证格式；不发送附件路径、PDF 原文、用户 ID、学校和工作单位名称。这不是完整匿名化。用户聊天、职业经历、模型回答仍会传给配置的模型供应商并保存数据库。
10. 日志记录任务 ID、白名单工具名、用量、耗时和异常类型，不输出消息正文、工具参数、响应正文或密钥。SSE 状态是业务进度，不是模型内部思维过程。

尚未实现：RAG、知识引用、专职多 Agent、自动写简历/投递、面试预约工具、模型质量评估看板。面试准备目前是通用对话，不能声称检索了知识库。岗位筛选中的硬条件仍需专项质量评估，提示约束不能保证模型始终正确理解自然语言条件。

## 记忆功能（2026-10-21）

记忆始终自动开启，客户端已移除「记忆管理」页面、入口与开关，不需要用户设置。旧版本关闭过记忆的账号在首次使用新服务时也恢复开启，数据库字段保留以兼容原表结构。本次调整无需新增 SQL。

- 消息写入 MySQL 后，后端生成回答前自动读取本账号当前会话近期消息，最多 16 条、24000 字符；此前已摘要或已清除上下文范围内的消息不再重复注入。返回历史会话可以继续使用已保存消息和摘要，重启 App 不影响持久化数据。
- 既有已确认长期偏好仍会自动注入新会话。客户端不再提供新增/编辑偏好表单，后台保留归属校验后的存取接口；没有自动提取偏好或模型写记忆工具，不能把普通聊天声称为已新增跨会话偏好。支持意向城市、目标岗位、薪资要求、工作方式、回答风格、交流语言、学习目标，每类一条，最多 200 字。当前消息要求优先。常见邮箱、手机号、身份证号和密钥关键词会被拒绝，但不能视为完整敏感信息识别。
- 会话较长时，在生成答案前最多调用一次同一供应商模型，将较早的已完成对话压缩成不超过 2000 字符的摘要；最新 8 条不参与本轮压缩，每次按消息 ID 顺序最多压缩 24 条，单条最多 1000 字，摘要仅用于所属会话。长历史会逐轮推进，极长的旧历史不保证全部覆盖。模型摘要可能遗漏或出错，摘要通过后端接口读取与重置。
- 摘要调用共享任务总时限，另限制 15 秒，不重试；失败时退回已有摘要和近期消息，不阻断回答。摘要调用次数和成功返回的 Token 加入任务计数；失败请求的供应商实际计费可能无法获取。摘要不会作为答案流式输出。
- 保存/修改/删除、重置接口都会清除本账号所有摘要，并记录全局消息 ID 边界；之后不再向模型注入边界以前的原始历史，避免删除内容被历史重新带回。原聊天记录仍保留供查看，不等同于数据擦除，也无法删除供应商已收到的数据。
- 任务创建与记忆修改共用账号行锁；修改要求本账号没有运行中的任务，避免回答继续使用修改前加载的记忆。冲突返回 409，需先停止回答。修改携带 revision，过期版本返回 409，刷新后重试，避免旧请求覆盖新内容。

新增后端位置：`AppAiMemoryController`（ruoyi-admin）、`AppAiMemoryService`、`AppAiMemoryMapper` 及对应 XML（ruoyi-system）。新增表 `t_capp_ai_memory_state`、`t_capp_ai_memory`、`t_capp_ai_summary`，全部按登录账号隔离。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/app/ai/memories` | `enabled/revision/items`；items 为 `memoryKey/value` |
| POST | `/app/ai/memories` | 后台保留：`action/revision`，action 为 save、forget、clear、reset_context；save 需 key/value，forget 需 key；settings 已移除，返回 400 |
| GET | `/app/ai/sessions/{id}/summary` | 所属会话摘要 `content`；无摘要时为空 |

记忆类型 key：`city/target_role/salary/work_mode/reply_style/language/learning_goal`。接口不接收用户身份参数。请求失败消息不回显偏好正文。

**表结构文件位置：`backend/doc/migration_capp_ai_memory_20261021.sql`**，在原 AI 四表迁移之后执行，可重复执行，只新增三张表。回滚文件：`backend/doc/rollback_capp_ai_memory_20261021.sql`；先回滚应用，再备份并按需删表，会丢失偏好及摘要，原会话和消息保留。`backend/tools/migrate_ai_local.py` 已包含两份迁移及七表核对，不在脚本中保存密码。实际本机执行状态以本次交付说明为准，文件存在不代表已执行。

对话历史操作由 `migration_capp_ai_history_actions_20261021.sql` 为会话表增加 `pinned` 字段；提供置顶、单条/批量删除，删除时在事务中清理事件、消息、摘要、任务及会话，并拒绝删除正在生成回答的会话。AI 任务选择上下文由 `migration_capp_ai_task_context_20261021.sql` 增加投递编号与任务类型，面试准备通过本人投递记录关联岗位和简历；回滚使用 `rollback_capp_ai_task_context_20261021.sql`。执行 AI 本机迁移脚本会应用并核验这些增量迁移。

快捷功能选择上下文：`POST /app/ai/sessions/{id}/runs` 可选接收 `action`（`chat`、`job_recommendation`、`resume_analysis`、`interview_preparation`、`writing_polish`）和本人 `applicationId`。岗位推荐与简历分析须传本人选择的 `resumeId`；面试准备须传本人已投递的 `applicationId`，服务端忽略客户端简历归属主张，读取投递关联的简历并核验岗位。`/agent/v1/applications` 分页列表供选择岗位，`GET /agent/v1/applications/{id}` 复核选择并返回岗位与简历名称。普通聊天不要求选择资料。

## 接口

所有接口需要登录。用户 ID 仅由登录态取得，AI 会话与 HR 消息不共用表，不影响「全部已读」。

| 方法 | 路径 `/app/ai` 下 | 说明 |
| --- | --- | --- |
| GET / POST | `/sessions` | 列表 / 创建；列表 `before` 字符串游标，每页 20 |
| GET | `/sessions/{id}/messages` | `before` 消息 ID 游标，每页 30；正序返回当前页及 `activeRunId` |
| POST | `/sessions/{id}/runs` | `{requestId, content, resumeId?}`；正文最多 4000 字符 |
| GET | `/runs/{id}` | 状态、计数与错误类型，不返回输入正文 |
| POST | `/runs/{id}/cancel` | 取消任务，无请求正文 |
| GET | `/runs/{id}/events?after=0` | SSE；`id` 是持久化事件游标 |

普通接口为若依 `code/msg/data` 包装。SSE 使用 `status`（`text`）、`delta`（`text`）、`cards`（`items`）、`done`（`status/errorCode`）；每 10 秒心跳。终态为 `COMPLETED/FAILED/CANCELLED`。常见错误：401 身份失效、404 不存在或越权、409 当前任务冲突、503 无配置/繁忙。开始返回前的网络异常不能等同于任务未创建，必须使用同一个 requestId 恢复。

正文校验错误返回业务 `code=400`，不让全局异常日志记录被拒绝的聊天正文。用量指标在取消、进程退出等情况下可能不完整，不作为供应商账单依据。

### 回答失败与重新生成（2026-10-21）

- 连接或 TLS 握手异常返回任务错误码 `CONNECTION_FAILED`；模型请求或任务时限耗尽返回 `TIMEOUT`。客户端只显示可执行提示，不回显供应商异常、地址或凭据。
- 最新一条问题回答失败时，错误栏提供「重新生成」，读取原任务归属校验后的元数据，沿用原问题和原简历上下文创建新任务，不再只刷新历史。重进失败会话也会恢复错误原因及重试入口；取消的任务不自动重试。
- 失败可能发生在客户端订阅 SSE 之前，因此加载历史时也检查最新失败任务，不依赖 `done` 事件才能发现错误。重试元数据查询期间禁止重复点击；页面销毁后忽略迟到结果。发送结果不明确时仍复用 requestId，已明确失败后重试使用新编号。
- 已验证：Flutter 静态分析、全部 75 项测试；后端 AI 服务、工具及流式解析共 28 项测试（模型桩与 H2）。本机真实 DeepSeek TLS 连接失败尚未恢复，不能将模拟测试结果视为真实模型调用通过；后端错误分类需重新打包并重启后生效。本次未修改 SQL 或表结构。

## 部署与回滚

1. 在本机/目标数据库执行 `migration_capp_ai_agent_20261020.sql`；只新增四张表，不修改现有业务表。先检查当前库正确，使用本机数据库工具认证，不把密码写入命令或文档。
2. 确认后台至少有一个启用且支持工具调用的模型 Provider；不会打印或修改现有密钥。无配置时不会伪造回答。
3. `mvn -pl ruoyi-admin -am test`，随后 `mvn -DskipTests package`，按现有本机配置启动新后端。不要在运行进程占用 JAR 时重新打包；不要在未具备重启凭据时停止现有服务。
4. 反向代理对 `/app/ai/runs/*/events` 关闭缓冲，读取超时至少 180 秒；服务已返回 `X-Accel-Buffering: no`，部署仍需验证实际代理行为。
5. Flutter 格式、analyze、test 和 Android Debug 构建后，登录测试账号验证「新会话 → 选简历 → 推荐 → 查看岗位 → 停止/重连 → 重进历史」。真实模型、MySQL 和设备闭环需独立验收，不能用模拟测试替代。

回滚先切回不包含 AI 功能的客户端/后端。四张表可保留以保存会话；如明确删除功能和全部历史，再备份并执行 `rollback_capp_ai_agent_20261020.sql`。聊天和事件表含私有数据，备份、保留期限及清理按部署方数据策略处理，禁止提交数据库导出。第一版未提供聊天删除入口和自动保留期限清理。
