# 生产数据库迁移前只读核查手册

- 版本日期：2026-11-10（封版补丁：4.3/4.4 新增快照五表统一存在数，部分存在 1–4 张判 BLOCKED_PARTIAL_SNAPSHOT_SCHEMA，不再误判 NOT_APPLICABLE）
- 适用项目：企业简历快照迁移（feature/eapp-core-services-zx）
- 前置事实：MySQL 8.0.46 一次性 Testcontainers 隔离演练 14/14 PASS（隔离通过 ≠ 生产通过）
- 本手册定位：正式迁移前由**人工手动执行只读 SQL**，核对生产真实结构与数据；本手册及配套 SQL 不执行任何写入

## 一、安全边界

- 本轮不连接数据库、不执行 SQL、不启动 Docker、不部署；配套脚本由本人在生产库手动执行。
- 每个 SQL 开头均有 **0.0 `SELECT DATABASE()`**，执行前先核对 current_database 为目标库；若不符立即停止，避免误在其他库执行。
- 4 个配套 SQL 仅含 SELECT 与 information_schema 读取；词法级静态检查共 44 个可执行语句（11+19+5+9），全部以 SELECT 开头，无 INSERT/UPDATE/DELETE/ALTER/DROP/CREATE/RENAME/CALL/PREPARE/EXECUTE（注释中的说明性文字除外）。
- 发现异常只记录、不自动修复；不得为通过核查修改正式迁移方案、删除异常判断或清空异常数据。

## 三、配套 SQL 与执行顺序

建议按下列顺序执行；先跑 1.x 确认表存在性，再决定是否执行“建表后”段落。

| 顺序 | 文件 | 覆盖范围 |
|---|---|---|
| 1 | 生产表结构只读核查.sql | 六目标表存在性、字段、索引、主键、外键 |
| 2 | 生产 AI 分析记录核查.sql | AI 表迁移阶段判定、主键/索引/多版本/外键 |
| 3 | 生产字段类型及精度核查.sql | 时间列类型精度、ID/哈希宽度、字符集 |
| 4 | 生产历史数据只读诊断.sql | 数据规模、来源、重复、引用完整性、PDF 可恢复性 |

每条查询的预期结果、异常判定与处理建议已写在对应 SQL 的段落注释中，执行时逐段对照。

### 表存在性预期（P2-1，依据 02_schema.sql 建表与现有系统对象）

- **t_ai_candidate_analysis 必须存在**：它是现有业务表，迁移在其上加列/改主键；缺失即 BLOCKED_REQUIRED_MISSING。
- **快照五表首次迁移前允许不存在**：02 用 IF NOT EXISTS 建表，全部缺失（1.1-bis 计数 0）属干净待建，可首次迁移。
- **部分存在（计数 1–4）标记 WARNING_PARTIAL_PRESENT_BLOCK_REVIEW**：非干净中间态，须人工确认是否为失败/中断的历史迁移，核对结构后再决定继续或清理，禁止盲目补建。
- **全部已存在（计数 5）标记 WARNING_ALL_PRESENT_VERIFY**：须逐字段核对是否与 02 一致，确认无版本漂移后方可继续。
- 1.1 固定返回 6 行（派生表 LEFT JOIN information_schema），缺表显示 MISSING 而非空结果，避免缺表被漏看误判。

### 快照五表部分迁移状态判定（封版口径，4.3/4.4 统一执行）

- 五张表**全部不存在（snapshot_tables_present=0）**：干净待建，允许首次迁移，缺失表判 NOT_APPLICABLE。
- 五张表**存在 1–4 张**：属部分迁移或中断状态，缺失表/主表一律判 **BLOCKED_PARTIAL_SNAPSHOT_SCHEMA，必须阻断人工审核**，不得误判为首次迁移前的 NOT_APPLICABLE。
- 五张表**全部存在（=5）**：逐表检查字段、类型、索引、字符集；计数 5 却有表缺失属理论矛盾，判 MISSING_REQUIRED。
- 发现部分存在时，**不得自动补表、删除表或清理数据**，必须先人工核对是否为失败/中断的历史迁移，再决定继续或回滚。

## 四、重点核查口径

### 4.1 AI 表迁移阶段（由 3.5 输出，严格多要素判定，禁止仅凭主键列数）

3.5 内层输出 pk_columns（主键列名及顺序）、asr_id_present、added_column_count（02 六字段 0–6）、dr3_index_present（DR3 索引名称是否存在）、dr3_index_ok、**idx02_present_count（02 四索引“名称”实际存在数 0–4）**、idx02_ok_count（02 四索引结构正确数 0–4），外层综合判定。索引结构校验五要素：**non_unique=1、index_type=BTREE、列数量、列顺序、sub_part 全 NULL**：

- STAGE0_ORIGINAL：复合主键列名顺序正确、无 asr_id、02 六字段全缺（0）、DR3 索引不存在、**02 四索引名称全部不存在（idx02_present_count=0）** → 正向迁移从 01 开始。
- STAGE1_AFTER_02：复合主键正确、无 asr_id、02 六字段齐全（6）、DR3 索引不存在、**02 四索引结构全部正确（idx02_ok_count=4）** → 下一步执行 DR3 重构。
- STAGE2_AFTER_DR3：主键明确为 asr_id、02 六字段齐全、**DR3 三元组索引结构正确（五要素）、02 四索引结构全部正确（=4）** → 可进入回填/校验。
- INCONSISTENT：其他任何结构组合（如 asr_id 存在但主键非 asr_id、字段半齐、索引缺名/缺 BTREE/前缀）→ BLOCKED，停止并人工核对。
- 02 四索引定义取自 02_schema.sql 的 p_ensure_index（均非唯一/BTREE/无前缀）：idx_asr_app、idx_asr_snapshot、idx_asr_company_candidate、idx_asr_company_position；**3.7 与 3.5 内 dr3_index_ok 完全同一 HAVING 口径（含 BTREE），判定一致**。

### 4.2 重复三元组与多版本

- 阶段0/1 出现重复三元组理论不可能（复合主键约束），出现即 BLOCKED。
- 阶段2 多版本为预期；用 3.10 核对 llm/manual/NULL 计数，NULL 来源须经 03 识别，不默认 llm。

### 4.3 字段类型、精度与可空性（预期清单 LEFT JOIN，缺失必显 MISSING）

4.1（AI 表固定 8 行：原始 asr_updated_at + 02 六字段 + DR3 asr_id）、4.2（快照主表固定 10 行）均为预期字段派生表 LEFT JOIN information_schema.columns，预期字段逐一输出，不再因字段缺失返回空集被误判 PASS：

- 字段存在：先判 column_name 再判 data_type；类型/宽度/精度通过后，再依次校验自增与可空性。
- 类型/宽度不符输出 RISK_TYPE_REVIEW；asr_id 缺 AUTO_INCREMENT 输出 RISK_NOT_AUTO_INCREMENT；**实际 is_nullable 与 expected_nullable 不一致输出 RISK_NULLABILITY**；全部符合输出 OK_BIGINT/OK_DATETIME/OK_VARCHAR。
- 字段不存在：当前阶段 REQUIRED 输出 MISSING_REQUIRED；当前阶段尚未执行相关迁移输出 NOT_APPLICABLE。
- 表未建立：整表字段输出 TABLE_MISSING（快照主表首次迁移前正常，不逐个误判异常）。
- 硬性宽度（不降低）：5 个 ID 必须 bigint；asr/ers_content_hash 必须 varchar 宽度≥128；ers_file_path 必须 varchar 宽度≥500；ers_file_name 必须 varchar 宽度≥255；asr_source 必须 varchar 宽度≥10；**asr_version_status 为 varchar(24)，依据 02 定义，无猜测**。
- 预期可空性（依据正式 DDL）：asr_updated_at、asr_id、5 个 ID、ers_created_at 为 NO；02 六字段、ers_snapshot_at、ers_file_path/name、ers_content_hash 为 YES。
- 字符集阶段语义（4.3 表级、4.4 列级，统一统计五表存在数 snapshot_tables_present，预期清单 LEFT JOIN，utf8mb4 标准不改变）：
  - AI 分析表缺失：BLOCKED_TABLE_MISSING（阻断）。
  - 快照五表**全部不存在（=0）**且当前表缺失：NOT_APPLICABLE（不阻断，可首次迁移）。
  - 快照五表**部分存在（1–4）**且当前表缺失：**BLOCKED_PARTIAL_SNAPSHOT_SCHEMA（阻断，中断/部分迁移态）**；计数 5 却理论缺失：MISSING_REQUIRED。
  - 4.4 快照主表缺失时同样按 0/1–4/5 区分 NOT_APPLICABLE/BLOCKED_PARTIAL/MISSING_REQUIRED；主表存在但字段缺失：MISSING_REQUIRED。
  - asr_source/asr_content_hash 在 02 未执行（added=0）时缺失：NOT_APPLICABLE；02 已执行仍缺失：MISSING_REQUIRED（AI 判定不受五表统计影响）。
  - 已存在字段字符集不符：RISK_CHARSET；符合 utf8mb4：OK_UTF8MB4(_COLUMN)。
  - 列级清单固定 5 行，含新增 **ers_file_name**（asr_content_hash、asr_source、ers_content_hash、ers_file_path、ers_file_name）。

### 4.4 元数据空结果处理规则（P2-2，零行不得自动解释为 PASS）

- 预期清单类查询（1.1、4.1–4.4）固定行数输出，缺表/缺列显 MISSING 或 TABLE_MISSING，从结构上消除“空结果”。
- 无外键查询（1.6/1.7、3.8）返回 0 或 0 行即“无外键”；表名硬编码且 0.0 已确认库，结论可信。
- 重复类查询（2.4、2.9）无行返回即“无重复”，分别对照 2.5 标量=0 确认。
- 计数类查询均返回标量（含 COALESCE 兜底），不会因无数据返回空集。
- 区分三种“不适用”：字段缺失（MISSING_*）、表缺失（TABLE_MISSING）、当前阶段不适用（NOT_APPLICABLE）。

### 4.5 六态状态统计（2.6，NULL/合法/非法分别识别）

2.6 不再用 COALESCE 把 NULL 与真实 -1 混淆，按 status_class 输出：NULL、LEGAL_0_5（0–5 并附中文状态名）、ILLEGAL_NEGATIVE（<0）、ILLEGAL_OVER_5（>5）；任一非合法分类标记 BLOCKED，人工核对 raw_value。

### 4.6 条件执行说明

- 2.2 来源分布（派生列 asr_source）仅在 02 加列完成后执行，未加列跳过改用 2.3。
- 快照五表相关查询（2.14–2.17）在表建立后执行，表未建一律跳过。
- 2.12b 仅在 2.12a 输出 COLUMN_EXISTS 时执行。

## 五、生产 PDF 迁移准备（文件核查清单口径）

数据库只能判断路径字段，**路径非空不等于对象真实存在**；对象存在性与哈希由受控文件核对程序验证。

- 清单文件：真实运行 `migration_file_verification_manifest.csv`，dry-run `dry_run_file_verification_manifest.csv`；UTF-8，14 列固定顺序，布尔 TRUE/FALSE。
- 证据分层（对应 14 列）：source/target 路径与存在性、各自大小与 SHA-256、copy_verified、archive_integrity_verified、archive_reference_sha256、authenticity_verified、final_classification、detail。
- 五类证据情形：
  1. 原始 PDF 可读取；
  2. 原始 PDF 缺失但存在独立历史哈希（参考哈希独立固化，禁止用当前目标哈希自证）；
  3. 目标已复制且哈希一致；
  4. 目标存在但无法证明原件真实性；
  5. 路径存在但实际对象不存在。
- 禁止：以路径非空认定文件存在、以目标当前哈希充当原件哈希、伪造历史时间与来源。
- 最终分类使用锁定的 10 类（如 SOURCE_MISSING_NO_FILE、ARCHIVED_UNVERIFIED、MANUAL_REVIEW 等）。

## 六、正式迁移前置条件判定矩阵

| 条件 | PASS | WARNING（人工确认，不自动升级） | BLOCKED（禁止继续） |
|---|---|---|---|
| AI 表主键/索引 | 符合当前阶段 | 非预期普通索引 | 阶段判定 INCONSISTENT、外键引用本表 |
| 字段类型 | 秒级 datetime、宽度达标 | 字符集/排序规则差异 | timestamp 未评估、哈希列宽度不足 |
| 重复三元组 | 与阶段相符 | 阶段2 多版本来源待识别 | 阶段0/1 出现重复 |
| 历史来源 | 来源明确 | 部分 NULL 待 03 识别 | 无法确认且无证据 |
| 简历关联 | 引用完整 | 少量软删/待核实 | 关键关联大面积缺失 |
| PDF 原件 | 可读或有独立历史哈希 | 真实性待证 | 原件缺失且无任何哈希证据 |
| 备份/归档表 | 不存在（可新建） | — | 同名归档表已存在且未确认 |
| 目标表结构 | 与 02 定义一致 | 字段可空性差异 | 迁移目标表结构不完整 |

| 2 | 02_schema.sql | 建五表、AI 表加列加索引、time_source 升级 | 01 通过 | 过程内守卫 SIGNAL |

## 八、隐式提交、失败处理与回滚

- DDL（CREATE/ALTER/RENAME 等）触发隐式提交，**不能用事务 ROLLBACK 撤销**；所有 DDL 已封装在存储过程并设前置守卫，顶层无裸 DDL。
- 中途失败：按各脚本“失败恢复”说明处置，保留现场与日志，不盲目重跑；RENAME 后归档表保留即恢复证据。
- 完整回滚：人工执行 05_rollback.sql，回滚后用其第五部分只读核验，确认结构与原始 DDL 一致、归档数据零丢失。

## 九、生产环境尚待确认的风险

1. 源表（t_res_base 及子表）真实 DDL 缺失，类型/日期精度须 information_schema 现场确认。
2. 时间列若为 timestamp/datetime(6)，存在时区或小数秒截断风险，未评估前不得执行 MODIFY。
3. 历史 AI 来源 NULL 与历史 PDF 缺失的真实数量，待手动执行诊断 SQL 后量化。
4. 真实对象存储中文件的存在性与哈希，须由受控文件核对程序验证，不能仅据数据库路径判断。

## 十、结论
