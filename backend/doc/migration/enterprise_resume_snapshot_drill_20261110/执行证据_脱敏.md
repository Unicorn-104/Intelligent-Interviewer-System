## 3. 缺陷真实错误证据（测试内捕获并经断言核对）

- DR-1（已隔离）：正式 SQL 引用 information_schema.statistics 的 `subpart`，真实容器抛
  `Unknown column 'subpart'`；MySQL 8 真实列名为 `SUB_PART`。测试侧按词边界替换为修正副本，不覆盖正式文件。
- DR-2（FAIL）：旧表缺 `ers_snapshot_at` 时执行 02，真实抛
  `Unknown column 'ers_snapshot_at'`（迁移过程先在 UPDATE 引用、却未先 ADD 该列）。
- DR-3（FAIL）：真实复合三列主键表执行 05 回滚，被守卫2中止，
  消息含“原表主键不是单列主键”，RENAME 未发生、原表行数不变。

## 4. 关键行为证据（断言）

- 场景 A：历史时间 `2026-01-05 10:00:00` 原样保留，未被 NOW() 覆盖；AI 来源由 JSON 识别为 llm，非默认值。
- 场景 D：前 1024 字节相同、尾部不同的长 TEXT 仍检出差异；12 个日期列 data_type 全部为 date。
- 场景 E：copy/archive/authenticity 三态分离，authenticity 默认 FALSE；危险前缀 `=1+1`、`@SUM(A1)` 被前置单引号。
- 场景 F：归档表 4 行零删除，manual-only 组不写入新表，企业快照五表保留。
- 场景 G：源简历 UPDATE/DELETE 后，快照主表与技能/工作子表查询结果零变化；跨企业查询计数 0。
- 06：剥离注释后无可执行 UPDATE；文件事实回写首次影响 1 行、重跑 0 行、错误 app_id 守卫 0 行，状态保持 REBUILT_UNVERIFIED。
