# 生产迁移最终执行手册

> 适用项目：Intelligent-Interviewer-System（分支 feature/eapp-core-services-zx）
> 目标库：recruit_agent（企业简历独立存储 + AI 多版本改造）
> 交付日期：2026-11-10
> 执行方式：**全流程由用户本人手动执行，本手册不自动连库、不执行任何写操作。**

## 一、生产基线（已由用户手动只读核查确认，禁止替换为假设值）

| 维度 | 确认结果 |

## 二、安全边界（强制）

- 禁止 AI 连接生产/服务器/其他本地持久化库，禁止执行生产 SQL（含 SELECT）、DDL/DML/CALL、回填、回滚。
- 禁止 Docker Compose、真实 S3/RustFS、改真实 PDF、部署/上传/重启、git commit/push/reset/clean。
- 不改变六态（0 已投递、1 招聘中、2 待发Offer、3 待确认Offer、4 已录用、5 未录用），不删除 t_tal.tal_status 业务字段。
- 不删除/清空/覆盖历史分析，不伪造历史时间、AI 来源、PDF 哈希。
- 数据库凭据、密码一律不写入 SQL/代码/日志/手册。

## 四、阶段 A：备份与环境检查

### A.1 前置条件
- 已确认维护窗口；通知并暂停 C-App/E-App 写入（建议停应用或启用只读/灰度下线）。
- 已确认连接目标为 recruit_agent（执行前先 `SELECT DATABASE();` 核对）。

### A.2 完整备份（缺一不可）
1. 逻辑备份：使用 mysqldump 对全库（至少覆盖 t_app_record、t_tal、t_res_base、t_res_education、t_res_work、t_res_project、t_res_skill、t_ai_candidate_analysis）导出，含 routines/events/triggers，记录文件名与大小。
2. 物理备份：按服务器现有备份机制做一次物理快照或数据目录备份。
3. 对象存储：对当前简历 PDF 所在命名空间做一份独立副本/快照（本线不连接对象存储，由用户执行）。
4. 备份验证：核对备份文件可列出、大小非 0；在隔离环境做一次恢复演练（恢复到临时实例并 `SELECT COUNT(*)` 与生产基线核对：AI 16、投递 10）。
5. 恢复验证目标：证明备份可在独立实例成功拉起并读到一致行数，方可进入 B。

### A.3 环境只读复核
- 引用 production_readonly_check_20261110/ 下 4 份只读 SQL（顺序见《生产迁移 SQL 执行顺序与核验清单.md》）。
- 该步骤结果应与本手册第一章基线一致；任一不符即停止排查。

### A.4 停止条件
- 备份缺失/无法恢复/行数对不上；连接目标不是 recruit_agent；写入未暂停。出现任一即停止，不进入 B。

## 五、阶段 B：数据库结构迁移

### B.1 01_precheck.sql（真正只读，12 项检查）
- 前置：A 已完成。用途：核对依赖 8 表齐全、六态合法、异常引用、软删、重复、来源、索引、字段。
- 预期：检查 2 依赖表 8 行；检查 3 无非法状态；检查 10 无“需停止”项；检查 11 无同名异结构。
- 停止：出现“需停止”项或依赖表缺失即停止，不进入 02。
- 可重复执行（纯 SELECT），无需回滚。

### B.2 02_schema.sql（DDL 封装在存储过程，顶层无裸 DDL）
- 前置：01 通过。用途：建企业快照五表（CREATE TABLE IF NOT EXISTS）、给 AI 表加 02 六字段（ADD COLUMN IF NOT EXISTS，均 DEFAULT NULL）、确保 02 四索引（p_ensure_index）。
- 操作：文件内 CALL 默认注释；审核后由用户**取消注释并手动 CALL** p_ent_schema_migrate()。
- 预期对象：五张 t_ent_resume_* 表；AI 表新增 asr_app_id/asr_snapshot_id/asr_content_hash/asr_source/asr_version_status/asr_created_at；02 四索引（均非唯一、BTREE、无前缀）。
- 不删除历史数据；过程内仅对旧遗留索引做有前缀排除的 DROP INDEX（不删行）。
- 停止：执行期守卫 p_ent_preflight_guard 失败即中止；此时未产生结构变更，可修正后重跑。

### B.3 DR3_主键重构_待审核.sql（单条 ALTER，表重建一次）
- 前置：02 已完成。用途：DROP 旧主键，ADD asr_id BIGINT NOT NULL AUTO_INCREMENT FIRST，ADD PRIMARY KEY(asr_id)，ADD KEY idx_asr_company_position_candidate(company,position,candidate)。
- 操作：CALL p_dr3_pk_rebuild() 默认注释，审核后手动执行。
- 预期：原有 16 行全部保留、不删行、不改 asr_report，AUTO_INCREMENT 自动为每行赋独立 asr_id；三元组降为普通索引。
- 停止：前置守卫失败即中止（未 ALTER，无数据损失）。
- 回滚：未产生多版本前可用文件内 p_dr3_pk_rebuild_rollback；已多版本则改用 05 归档式回滚。

### B.4 DDL 隐式提交（重点）
- CREATE/ALTER/DROP INDEX、CREATE/ALTER TABLE 均为 DDL，**MySQL 隐式提交，无法用事务整体回滚**。
- 每步执行后立即用核验 SQL 确认结构，再进入下一步；失败按 05 或备份恢复，不依赖事务回滚。

## 六、阶段 C：历史数据回填（03_backfill.sql）

- 前置：B 全部完成并核验。
- 步骤 1：以全部 t_app_record 为入口建快照主表（LEFT JOIN t_res_base，NOT EXISTS 幂等）。**无 rbs_status 过滤**：主记录存在即 REBUILT_UNVERIFIED；主记录缺失才 MISSING_SOURCE；PDF 三列先写 NULL（不影响结构化）。
- 步骤 2：按 ers_source_resume_id 回填教育/工作/项目/技能四子表（INNER JOIN，NOT EXISTS 幂等）；源子表被清理则对应子表为空，不报错、不中断。
- 步骤 3 起：AI 来源与绑定按证据回填，无法精确绑定者保持 UNVERIFIED、两 ID 保持 NULL，禁止猜测。
- 预期：10 条投递各建 1 条快照（含 2 软删）；3 条 PDF 空路径不阻断；16 条 AI 行不被删改。
- 停止：出现孤儿投递（t_tal 缺失）或行数异常即停止，人工核对后再补建。

## 七、阶段 D：完整性验证（04_verify.sql，全部 SELECT）

- 前置：C 完成。
- 覆盖：校验 1 投递数=快照数（gap=0）；校验 3 每 app_id 仅 1 条；校验 4/5 未生成/孤儿；校验 6 码值合法；校验 7 状态/时间/版本证据；校验 8 子表多重集 COUNT 双向 + 行哈希 SHA-256；校验 9 子表孤儿；校验 10 AI 绑定完整性；校验 11 来源分布与待人工清单；校验 12 PDF 引用。
- 通过标准：校验 1 gap=0；校验 3/4/5/6/7/9/10 无异常输出；异常项均按“待核实”语义保留。
- 停止：任一硬性校验有输出即停止，不进入部署。

## 八、阶段 E：PDF 迁移与人工回写

- 工具：HistoricalResumeMigrationConsole（dry-run 默认 true，只读不写）。
- 顺序：先 dry-run 输出计划与 14 列清单 → 人工核对 → 显式设 dry-run=false 真实迁移（CREATE_NEW 不覆盖、读回哈希核验）。
- 3 条空路径：不进入迁移工作清单，归类 SOURCE_MISSING_NO_FILE 进人工核查；不伪造文件/哈希/真实性。
- 7 条非空路径：其对象真实存在性与 SHA-256 为 NOT_VERIFIED，需由工具读回逐个核验，本线不连真实对象存储。
- 06 回写 SQL：工具生成的文件事实回写 SQL **保持注释/不自动执行**，由用户逐条审核后手动执行。

## 九、阶段 F：部署与验收（仅手册）

- 数据库迁移与核验通过后，按《后端部署及功能验收清单.md》构建、部署、做 T1–T10 与六态回归。本阶段不实际部署。

## 十、阶段 G：回滚（05_rollback.sql，不进正向序列）

- 归档式：整表 RENAME 为历史归档表（零 DELETE，完整保留所有行），再重建旧结构并按“每组优先 llm、再取最新”回填；manual 与多版本完整留存归档表。
- 企业快照五表与企业 PDF 默认保留，不自动 DROP。
- 适用条件、与备份恢复区别、无法自动恢复项，见《正式迁移前阻断问题清单.md》及《生产迁移 SQL 执行顺序与核验清单.md》。

## 十一、放行条件（同时满足）

1. 备份可恢复且行数核对一致；2. 01/02/DR3/03/04 全部按序通过，硬性校验无异常；
3. 16 条 AI（含 1 条 manual）逐条可追溯、报告未改写；4. 异常项均“待核实”，无伪造；
5. 回滚材料就绪；6. 已就详情页简历/PDF 仍读当前简历的 WARNING（阻断清单 W1）作出决策：
   接受遗留并记录边界，或批准补齐投递级快照接口后再上线。满足后进入人工审核，由用户批准并手动执行。

> 静态通过 ≠ MySQL 通过，隔离通过 ≠ 生产通过。本手册结论基于源码与离线/隔离验证，不代表生产已迁移。
