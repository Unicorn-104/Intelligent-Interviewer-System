## 三、面试日程与 PDF 接口兼容性

### 3.1 面试日程 applicationId 标量子查询

- 子查询仅引用 t_app_record（别名 ar）的 app_candidate_id/app_position_id/app_status/app_id/app_created_at，**不引用任何快照五表**。
- STAGE0：t_app_record 已存在且上述列齐全（app_created_at NOT NULL DEFAULT CURRENT_TIMESTAMP）→ 可执行。
- 迁移后：t_app_record 结构不变 → 可执行。
- 重复投递规则：非终态恰 1 条取该条；仅 1 条终态取唯一；其余（多非终态/多终态/无时间证据）返回 NULL，前端隐藏原件入口；加 app_created_at<=apt_start_time 约束，不简单取最新。
- 测试侧 H2 已补 app_created_at 列（仅改测试建表，未改生产 SQL）。

### 3.2 PDF 投递接口依赖边界

- `getApplicationResumePdf` 实际调用链：requireOwnership（t_app_record join t_pos）→ selectByAppId（t_ent_resume_snapshot）→ enterpriseStorage.read（企业独立对象存储）。
- **不依赖 rbs_status、不读 C-App 私有命名空间 private-resume、不调用 resumePdfStorage**。
- 类中 resumePdfStorage.readResource 仅存在于私有 readSourcePdf，用于快照创建链路，与投递级读取无关。
- 异常：路径空→"原始 PDF 不可用"；企业对象 404→"文件缺失"；均不回退 C-App；getCode() 已用常量反向比较防 NPE。

**面试/PDF 兼容性总评：PASS**（投递级接口依赖迁移后结构，实际生效 NOT_VERIFIED）
