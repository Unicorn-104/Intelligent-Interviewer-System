## 五、最小修改计划（待批准后实施）

### 5.1 后端（仅新增投递级读取，不删除旧 talId 接口）

1. **新增投递归属校验 Mapper 方法**（建议放 EntResumeSnapshotMapper 或 ApplicationStatusMapper）
   - 入参 appId + companyId，join t_pos 校验 pos_company_id；查不到即无权访问。
2. **EntResumeSnapshotService 新增两个只读方法**
   - `getApplicationResumeView(Long userId, Long applicationId)`
     - 归属校验 → `selectByAppId` 取快照；
     - 快照为 null → 抛 `ServiceException("SNAPSHOT_NOT_AVAILABLE")`，**禁止回退当前简历**；
     - 将快照四子表转换为前端兼容 Map（educationList/workList/projectList/skills + integrity/missingFields + resumeScope=application_snapshot）。
   - `getApplicationResumePdf(Long userId, Long applicationId)`
     - 归属校验 → selectByAppId；
     - `filePath` 为空 → 抛「原始 PDF 不可用」；
     - `EnterpriseResumeStorage.read(filePath)` 读企业 PDF；对象不存在 → 抛「文件缺失」；
     - 全程不依赖 rbs_status、不读 private-resume。
3. **Controller 新增两个投递级端点**（建议新建 ApplicationResumeController，路径待确认，见 6.2）
   - `GET /enterprise/applications/{applicationId}/resume`
   - `GET /enterprise/applications/{applicationId}/resume/pdf`
4. **旧 talId 接口保留**，供人才库场景继续使用，不删除、不改签名。

### 5.2 前端（按 applicationId 分流，人才库保持 talId）

1. talent_api.dart 新增 `getApplicationParsedResume(applicationId)`、`getApplicationResumePdf(applicationId)`。
2. TalentDetailDataSource 新增 `loadApplicationResume(applicationId)`。
3. talent_detail_page.dart：当 `jobContext?.applicationId != null` 时，简历区块改调投递级接口；PDF 按钮携带 applicationId，TalentResumePdfPage 支持投递级 loader。
4. 岗位卡片展开（job_detail_data_source.loadCandidateResume）改为按行内 applicationId 调投递级接口。
5. conversation_page：从 `talent['applicationId']` 取出并传入 TalentJobContext（纯前端，数据已具备）。
6. 无 jobContext（人才库）：保持现有 talId 调用，不改动。
7. **禁止**根据 talId 反推/猜测 applicationId。
