# RAG 与游客登录交付规范（2026-11-10）

## 功能、分支与范围

本轮完整交付包含「RAG 和游客登录」，姓名缩写由用户指定为 `MZR`。两个功能共用一个分支
`feature/capp-rag-guest-login-MZR`，统一一个 PR 到 `dev`，每个可独立理解、验证和回滚的子功能单独 commit。
分支格式为 `feature/<模块名>-<功能名>-<姓名缩写>`；本轮模块为 `capp`，功能为 `rag-guest-login`。

采用固定单向模型 `feature/* -> dev -> main`。从交付时最新 `origin/dev` 创建功能分支；
仅在远端没有 `dev` 时，先从最新 `origin/main` 创建并推送 `dev`。不得覆盖已有同名分支、
直接推送 dev/main、跳级合并或重写共享分支历史。

只提交 `backend/`、`c-app/` 中本轮相关代码、测试、迁移、文档及根目录 `AGENTS.md` 的本轮记忆。
不纳入其他端、独立长期记忆管理界面、面试开发增量、历史 SQL 删除、私有配置、凭据、真实资料、
聊天数据、模型缓存、依赖目录、日志、APK、JAR 和运行状态。`process.md` 只作本地开发依据。

原开发目录及全部已有修改保持原状。允许使用同一功能分支的独立 worktree 整理交付，
仅迁移原工作区相对其 HEAD 的相关增量，逐项合并 dev 新代码，不使用旧目录整体覆盖 dev。
交付目录与开发目录是两个工作目录，不表示两个功能分支。

## RAG 契约

- 当前是个人知识库，平台公共库仅预留字段；所有者从登录凭据获取，不接受客户端伪造身份。
- 支持文字型 PDF、DOCX、UTF-8 TXT/Markdown，限制、处理状态和接口见
  [个人知识库实现说明](../backend/doc/capp_knowledge_rag.md)。扫描 PDF、音频及生成内容归档未实现。
- 原文件复用现有私有存储，MySQL 保存资料、片段、任务和引用，Qdrant 保存可重建向量。
  知识库与长期记忆使用独立集合，检索先按所有者和范围过滤，再核验文档归属及有效版本。
- 先按说明执行仅新增知识库表的迁移，再显式启用 `app.ai.knowledge.enabled=true`。
  默认关闭，普通后端启动成功不等于知识库已启用。
- 明确配置 Embedding 地址、模型和维度及 Qdrant 地址；更换模型或维度时使用新集合并重建索引。
- Agent 默认检索本人可用资料，相关片段会发给已配置的模型供应商；没有个人资料依据时不得伪称已检索。
  普通聊天在资料服务故障时按实现降级；旧客户端显式资料范围仍保留严格模式。
- 历史回答保存来源；原资料删除或更新后显示来源不可用。引用可点击不等于答案质量已验收。
- 不自动执行生产迁移、重建生产向量、删除原文件或部署服务器。

## 游客与登录契约

- 未登录进入游客首页，可以浏览、搜索公开岗位并查看可公开的岗位详情。
- 游客不请求个人投递、面试日程、收藏状态等私人数据；简历、消息、我的等受限入口提供「不了 / 登录」。
- 个性化推荐明确提示登录后可用；登录后重建依赖会话的首页状态，退出后恢复游客首页。
- 只放行必要的公开 GET 路由，收藏、投递、面试、简历和知识库仍强制鉴权；不得以 `/app/jobs/**`
  等宽泛规则放开私人子接口。登录凭据不发送给岗位卡片或资料提供的外部链接。
- 公开搜索与登录搜索能力不同的部分必须如实显示，不把被忽略的筛选条件或截断结果展示成完整分页。
- 后端认证失败与未配置知识库分别处理，不能通过吞错或伪造空列表掩盖服务失败。

## 风险和回滚

RAG 依赖文件存储、MySQL、Embedding、Qdrant 和模型服务；知识库开关默认关闭，部署时漏配会显示未启用。
测试替身不代表真实供应商兼容或服务器验收，模拟器运行不代表 iOS、真机和发布构建验收。

先关闭知识库开关停止入口和处理，保留原文件与数据；需要回滚代码时使用 git revert 或 Revert PR，
保留共享历史。删除知识库表前停止 worker，备份并核对影响，按实现文档执行回滚脚本；
不自动删除原文件、既有 AI 表或个人数据。游客回滚同时恢复客户端入口与后端公开路由，避免两端契约不一致。
