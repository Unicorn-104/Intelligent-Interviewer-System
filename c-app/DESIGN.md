# 智聘助手 C-APP 设计系统

> 适用项目：企业级智能招聘面试官 Agent 系统 · 求职者移动端（C-APP）  
> 技术栈：Flutter / Dart  
> 设计方向：以用户 PC 端蓝色体系为主，融合根目录 `DESIGN.md` 的排版、间距、圆角与强调色原则。

---

## 1. 设计定位

智聘助手是一款面向求职者的智能招聘应用。产品需要同时传达三种感受：

- **可信赖**：深海军蓝用于品牌、标题和重要信息，体现招聘业务的专业性。
- **高效率**：亮蓝用于按钮、链接、选中态和进度，明确引导下一步操作。
- **有智能感但不过度科技化**：近黑 AI 重点区域配合彩色强调色，突出智能能力，但不使用大面积炫光、霓虹或复杂渐变。

整体采用浅灰页面背景、白色卡片、蓝色交互和低饱和边框。界面以信息清晰、操作直接、状态明确为第一目标。

---

## 2. 核心设计原则

### 2.1 信息优先

- 首屏优先展示职位名称、薪资、企业、城市和 AI 匹配度。
- 招聘进度、面试时间和待办操作必须比企业介绍等次要信息更醒目。
- 一张卡片只保留一个主要动作，避免多个同权重按钮争夺注意力。

### 2.2 蓝色负责交互，近黑负责重点

- 深蓝用于品牌、页面标题和核心文字。
- 亮蓝用于可点击、选中、聚焦、进度和主要按钮。
- 近黑用于 AI Hero、重点展示区域和极高优先级信息。
- 紫、粉、蓝、橙、绿等强调色只用于业务分类、状态或整块特色卡片，不作为普通按钮颜色。

### 2.3 克制的形状与层级

- 普通按钮圆角为 `4px`。
- 卡片圆角为 `8px`。
- 圆形只用于头像、图标容器、状态点和进度环。
- 默认使用细边框建立层级，仅对重点卡片使用轻量阴影。

### 2.4 AI 结果必须可解释

- AI 匹配度、诊断、建议和评分必须带有 `AI` 标识。
- AI 输出旁必须出现“仅供参考”“辅助建议”等提示。
- AI 结果不能表现为系统已经替用户或企业做出最终决定。

### 2.5 完整覆盖移动端状态

所有业务页面必须设计：

- 加载中
- 空数据
- 请求失败与重试
- 无权限
- 弱网或超时
- 重复提交
- 登录失效
- 文件上传失败
- 相机、麦克风和通知权限被拒绝

## 3. 色彩系统

### 3.1 品牌与交互色

| Token | 色值 | 用途 |
|---|---:|---|
| `brand` | `#1A3C6E` | 品牌主色、页面标题、重要文本、企业级视觉识别 |
| `brandDeep` | `#102D53` | 深色渐变终点、深色强调背景 |
| `interactive` | `#2B7FFF` | 主按钮、链接、选中态、焦点、进度、活动图标 |
| `interactiveSoft` | `#EAF2FF` | 选中背景、信息提示背景、蓝色标签底色 |
| `ink` | `#080808` | AI Hero、最高层级重点区域、近黑文字 |
| `onPrimary` | `#FFFFFF` | 深色或蓝色表面上的文字和图标 |

### 3.2 页面与文字色

| Token | 色值 | 用途 |
|---|---:|---|
| `canvas` | `#FFFFFF` | 卡片、输入框、底部导航、弹窗 |
| `background` | `#F5F7FA` | 页面默认背景 |
| `hairline` | `#E6EBF2` | 卡片边框、分割线、输入框边框 |
| `textPrimary` | `#172B4D` | 正文和主要信息 |
| `textSecondary` | `#4D5F78` | 次级正文、辅助描述 |
| `textMuted` | `#6B7A90` | 时间、占位符、低优先级元数据 |

### 3.3 分类与语义色

分类色沿用原始 `DESIGN.md` 的五色体系，作为整块特色卡片、业务分类或小面积标识：

| Token | 色值 | 推荐用途 |
|---|---:|---|
| `accentPurple` | `#7A3DFF` | AI 简历诊断、智能分析 |
| `accentPink` | `#ED52CB` | 沟通、互动、内容生成 |
| `accentBlue` | `#3B89FF` | 推荐、数据、信息类能力 |
| `accentOrange` | `#FF6B00` | 薪资、紧急招聘、重点提醒 |
| `accentGreen` | `#00D722` | 完成、通过类特色表面 |

语义状态采用更适合业务阅读的颜色：

| Token | 色值 | 用途 |
|---|---:|---|
| `success` | `#1B9A72` | 成功、已通过、在线、已完成 |
| `warning` | `#D7811D` | 待处理、即将开始、需要关注 |
| `warningSoft` | `#FFF4E5` | 警告信息背景 |
| `error` | `#EE1D36` | 失败、危险、删除、未读提醒 |
| `errorSoft` | `#FFF0F2` | 错误提示背景 |

### 3.4 色彩使用规则

- 页面中同一时刻只允许一个主要动作使用亮蓝实心按钮。
- 深蓝用于标题和品牌，不能与亮蓝按钮混为同一层级。
- 薪资默认使用橙色，但招聘状态不得只依靠颜色表达。
- 绿色文字应使用 `success`，不要直接用高亮 `accentGreen` 显示小号文字。
- 红色仅用于错误、危险操作和未读提醒。
- 彩色强调面必须保证文字对比度；绿色亮色表面使用深色文字，其余深色表面使用白色文字。

## 4. 字体系统

### 4.1 字体族

Flutter 字体回退顺序：

```dart
['Inter', 'PingFang SC', 'Microsoft YaHei']
```

- 英文和数字优先使用 `Inter`。
- 中文在 iOS 使用苹方，在 Windows/Android 环境使用微软雅黑或系统无衬线字体。
- 不引入与产品气质不符的装饰字体。

### 4.2 字号与字重

| 角色 | 字号 | 行高 | 字重 | 用途 |
|---|---:|---:|---:|---|
| `display` | 30px | 1.2 | 600 | 首页重点数字、核心结果 |
| `headline` | 24px | 1.3 | 600 | 页面主标题、欢迎语 |
| `titleLarge` | 20px | 1.4 | 600 | 大区块标题 |
| `titleMedium` | 16px | 1.5 | 500 | 卡片标题、列表主信息 |
| `bodyLarge` | 16px | 1.6 | 400 | 重要正文、表单内容 |
| `bodyMedium` | 14px | 1.55 | 400 | 默认正文 |
| `bodySmall` | 12px | 1.5 | 400 | 时间、标签、辅助信息 |
| `button` | 15px | 1.4 | 500 | 按钮文字 |

规则：

- 最大常规字重为 `600`，不使用 `800/900` 制造粗重感。
- 大字号可使用轻微负字距，小字号保持默认字距。
- 页面主标题使用品牌深蓝，正文使用 `textPrimary`，说明文字使用 `textMuted`。
- 金额、匹配度和状态可以使用 `600`，但不要整段加粗。

## 5. 间距与布局

### 5.1 基础间距

采用 `4px` 基础单位：

| Token | 数值 | 用途 |
|---|---:|---|
| `xxs` | 2px | 图标微调、细节间距 |
| `xs` | 4px | 标签内部、标题与说明 |
| `sm` | 8px | 同组元素间距 |
| `md` | 12px | 卡片内部小间距 |
| `lg` | 16px | 默认卡片内边距 |
| `xl` | 20px | 页面左右边距 |
| `2xl` | 24px | 页面区块间距 |
| `3xl` | 32px | 大区块和首屏留白 |

### 5.2 移动端布局

- 页面采用单列结构。
- 默认左右安全边距为 `20px`。
- 卡片内部默认使用 `16px`，重点卡片可使用 `20px`。
- 页面主要区块间距为 `24px`。
- 固定底部导航包含：首页、简历、消息、我的。
- 底部按钮必须避让系统安全区域。
- 内容最大宽度由设备决定，不在手机页面中使用 PC 式多列信息布局。

### 5.3 触控尺寸

- 主要按钮高度不低于 `46px`。
- 普通操作和图标按钮点击区域不低于 `44×44px`。
- 小标签仅用于展示，不能承担必须点击的核心操作。

## 6. 圆角、边框与阴影

### 6.1 圆角

| Token | 数值 | 用途 |
|---|---:|---|
| `radiusNone` | 0px | 全宽色带 |
| `radiusXs` | 2px | 极小装饰元素 |
| `radiusSm` | 4px | 按钮、输入框、标签 |
| `radiusMd` | 8px | 卡片、弹窗、重点容器 |
| `radiusFull` | 9999px | 头像、圆形图标、状态点 |

禁止将所有按钮设计成胶囊形。普通按钮统一使用 `4px` 圆角。

### 6.2 边框

- 默认边框：`1px solid #E6EBF2`。
- 输入框聚焦：`1.5px solid #2B7FFF`。
- 分割线尽量使用边框色，不使用高对比黑线。

### 6.3 阴影

普通卡片以边框为主，不默认添加阴影。重点卡片可使用：

```text
0 8px 24px rgba(26, 60, 110, 0.07)
```

AI Hero 可使用：

```text
0 8px 18px rgba(0, 0, 0, 0.12)
```

弹窗可提高阴影强度，但不得产生厚重的 Material 悬浮感。

## 7. 核心组件规范

### 7.1 顶部栏

- 背景与页面一致或使用白色半透明表面。
- 标题使用 `20px / 600 / brand`。
- 返回、通知和设置图标使用品牌深蓝或正文色。
- 页面滚动时不增加明显阴影，仅允许细分割线。

### 7.2 底部导航

- 背景为白色。
- 选中图标使用 `interactive`。
- 选中指示背景使用 `interactiveSoft`。
- 未选中图标和文字使用 `textMuted`。
- 未读数量使用红色圆形徽标，同时显示数字。

### 7.3 主按钮

- 背景：`interactive`。
- 文字：白色。
- 高度：至少 `46px`。
- 圆角：`4px`。
- 禁用状态降低对比度，并禁止重复点击。

### 7.4 次按钮

- 背景：白色。
- 边框：`hairline`。
- 文字：品牌深蓝或正文色。
- 圆角：`4px`。

### 7.5 危险按钮

- 优先使用红色文字或红色描边。
- 只有确认弹窗中的最终危险操作可以使用红色实心按钮。
- 撤回投递、注销账号、清空消息和取消面试必须二次确认。

### 7.6 输入框

- 默认白色背景、浅灰边框。
- 聚焦边框使用亮蓝。
- 占位文字使用 `textMuted`。
- 错误状态使用红色边框和具体错误说明，不能只显示红框。

### 7.7 卡片

- 背景：白色。
- 圆角：`8px`。
- 边框：`hairline`。
- 内边距：`16px` 或 `20px`。
- 卡片内部信息顺序应固定，避免同类卡片跳动。

### 7.8 职位卡片

信息优先级：

1. 职位名称与薪资
2. 企业名称与城市
3. 岗位标签
4. AI 匹配度、学历和经验
5. 投递按钮

规则：

- 薪资使用橙色。
- AI 匹配度使用带业务强调色的浅色标签，并显示百分比。
- 每张职位卡片只设置一个“投递”主按钮。
- 点击卡片主体进入职位详情，点击投递按钮不得同时触发卡片跳转。

### 7.9 AI Hero

- 背景由 `ink` 向 `brandDeep` 轻微渐变。
- 标题使用白色，说明文字使用半透明白色。
- AI 图标可使用亮蓝。
- Hero 内按钮使用白底深色字，形成与普通蓝色按钮不同的重点层级。
- 必须展示“AI 结果仅供参考”。

### 7.10 状态标签

- 已通过、已完成：绿色。
- 待确认、即将开始：橙色。
- 进行中、已安排：蓝色。
- 已失败、已取消、已拒绝：红色。
- 状态必须同时包含文字，不得仅使用颜色或图标。

### 7.11 空状态与错误状态

- 空状态包含简洁图标、明确标题、原因说明和一个可执行动作。
- 错误状态说明发生了什么，并提供重试入口。
- 无网络状态不得展示为“暂无数据”。

## 8. 页面框架

### 8.1 首页

```text
问候与通知
  -> 搜索框
  -> AI 求职助手 Hero
  -> 推荐筛选
  -> AI 推荐职位卡片
  -> 我的投递进度
  -> 底部导航
```

### 8.2 搜索与推荐

- 搜索框保持在首屏上方。
- 排序和筛选使用轻量 Chip 或底部弹层。
- 搜索结果数量、当前排序和空结果必须明确展示。

### 8.3 职位详情

- 首屏展示职位、薪资、企业、经验和学历要求。
- AI 匹配分析使用浅蓝信息卡，不抢夺职位主信息。
- “立即投递”固定在底部安全区域。

### 8.4 简历库

- 顶部使用紫色整块卡片展示 AI 简历诊断。
- 简历列表展示名称、完整度、更新时间和当前使用状态。
- AI 优化与编辑作为次级操作，新建简历作为页面底部入口。

### 8.5 投递详情

- 使用纵向时间轴展示招聘流程。
- 当前阶段使用亮蓝，已完成使用绿色，未开始使用浅灰。
- 面试临近时将时间、设备检查和进入面试按钮提前显示。

### 8.6 消息中心

- 分类为：全部、与 HR、AI 面试、系统通知。
- 未读数字使用红色徽标。
- AI、HR、系统和企业动态使用不同的小面积强调色图标。

### 8.7 个人中心

- 顶部展示头像、姓名、认证状态和求职状态。
- 投递、面试、收藏使用三项统计入口。
- 危险操作与普通设置分组，并放在页面底部。

## 9. 动效与反馈

- 普通点击反馈控制在 `100–180ms`。
- 页面切换使用系统默认或轻量淡入，不使用夸张的缩放和旋转。
- 列表刷新显示明确加载状态。
- 提交成功使用短暂 SnackBar；关键成功结果进入独立完成状态或结果页面。
- 按钮提交期间显示加载状态并禁用，防止重复提交。
- 骨架屏只用于结构稳定且预计等待时间较长的列表。

## 10. Flutter Token 映射

当前项目主题位于：

```text
lib/theme/app_theme.dart
```

推荐保持以下映射：

```dart
ColorScheme.primary       -> interactive (#2B7FFF)
ColorScheme.secondary     -> accentPurple (#7A3DFF)
ColorScheme.error         -> error (#EE1D36)
Theme.scaffoldBackground  -> background (#F5F7FA)
Theme.cardColor           -> canvas (#FFFFFF)
Theme.dividerColor        -> hairline (#E6EBF2)
```

组件不得在页面内随意新增近似颜色。新增颜色前应先判断能否复用已有 Token；确需新增时，应先更新本设计文档与 `AppColors`。

## 11. 可访问性

- 正文与背景应满足至少 WCAG AA 对比度。
- 文字缩放后不得被固定高度容器裁切。
- 图标按钮应提供语义标签或 Tooltip。
- 状态不能只依赖颜色表达。
- 表单错误需要文字说明并可被辅助功能读取。
- 重要操作的点击区域至少为 `44×44px`。

## 12. Do / Don't

### Do

- 使用深蓝建立品牌和标题层级。
- 使用亮蓝统一所有交互反馈。
- 使用近黑 AI Hero 营造重点和智能感。
- 保持白色卡片、浅灰背景和克制边框。
- 将分类强调色限制在状态、图标、标签和特色表面。
- 为所有真实业务页面补齐加载、空、错、弱网和权限状态。

### Don't

- 不要同时出现多个不同颜色的主要按钮。
- 不要大面积使用紫色或橙色替代品牌蓝。
- 不要使用超过 `600` 的常规字体字重。
- 不要将普通按钮设计为胶囊形。
- 不要用高饱和绿色显示小字号正文。
- 不要把 AI 评分表达成确定的录用结论。
- 不要在页面组件中散落未经定义的十六进制颜色。

## 13. 设计验收清单

每个页面完成后检查：

- 是否使用统一的品牌深蓝、交互蓝和页面背景。
- 页面是否只有一个视觉主操作。
- 按钮、输入框和卡片圆角是否分别为 `4px / 4px / 8px`。
- 是否使用 `20px` 页面边距和统一间距 Token。
- AI 内容是否明确标注并带辅助建议提示。
- 薪资、状态、未读和错误是否使用正确语义色。
- 是否覆盖加载、空数据、错误、弱网和权限状态。
- 小屏、刘海屏和底部安全区域是否正常。
- 文字放大后是否仍可完整阅读。
- 页面中是否存在未纳入 `AppColors` 的随意颜色。
