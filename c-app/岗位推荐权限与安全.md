# 岗位推荐权限与安全

适用入口：`POST /app/recommend`。保持选定简历后推荐岗位的现有接口与交互。

- 用户身份由 Controller 的登录态提供，不接收请求正文中的用户 ID。Service 再次拒绝空或无效用户 ID。
- 简历通过 `selectResume(userId, resumeId)` 校验归属；失败立即结束，不查询岗位、不调用模型、不走规则降级。
- 请求限制正数简历 ID、100 字符关键词及固定筛选枚举。候选池最多 50、返回最多 20，继续沿用既有限额归一化行为。
- 模型只提供岗位 ID、分数和理由。岗位字段始终来自后端候选池；不接受池外 ID、小数 ID、溢出 ID，重复 ID 仅保留首次结果。理由超过 500 字符时丢弃。
- 正常结果和降级结果返回前，批量复查岗位仍在招、企业仍正常。只检查原候选结果，不扩大候选集合；数据库复查失败直接失败，不返回未核实结果。状态复查后仍可能发生并发下架，后续详情和投递必须继续独立校验。
- 模型载荷去掉简历名称、学校名称和工作单位名称，不传附件路径、PDF 原文和用户 ID。经历描述仍可能包含用户自行填写的个人信息，这不是完整匿名化。
- 系统提示明确简历和岗位描述属于不可信数据，不执行其中指令，不要求输出隐私。提示只能降低注入风险，权限边界由后端代码和 SQL 执行。
- 模型调用异常日志只记录异常类型，不记录异常消息、模型响应、简历正文或密钥。

验证命令（在 `backend/` 执行）：

```powershell
mvn -pl ruoyi-system -am "-Dtest=AppRecommendSecurityTest,RecommendationAvailabilityTest" "-Dsurefire.failIfNoSpecifiedTests=false" test
```

测试使用合成数据及 H2，覆盖服务层权限与结果边界、真实 Mapper 的岗位和企业状态过滤。未替代真实 MySQL、登录 Token、设备和真实模型验收。无需数据库迁移；回滚时撤销本次推荐服务、请求校验、Mapper 增量和对应测试即可。

本轮不新增模型自主工具调用；未来增加工具时，每个工具入口仍须按登录态和资源归属独立授权，不能信任模型传入的用户 ID。
