# C-APP 与 Backend 提交及发布规范

本文补充本项目 `backend/` 和 `c-app/` 的协作要求，与 [仓库 Git 规范](../docs/spec/git.md) 配合执行，并由根目录 [AGENTS.md](../AGENTS.md) 作为项目 memory 引用。当前开发者姓名缩写为 **MZR**。

## 分支模型与命名

固定流转方向为 `feature/* -> dev -> main`。功能从最新 `origin/dev` 创建；若远端没有 `dev`，先从最新 `origin/main` 创建并推送 `dev`，再创建功能分支。若两个基线分支都不存在，先检查仓库初始化状态，不猜测基线。

分支格式为 `feature/<模块名>-<功能名>-<姓名缩写>`。模块和功能使用小写英文、数字与连字符，姓名缩写保留大写。本次按用户指定以「完善」为功能名，使用：

```text
feature/capp-improve-MZR
```

其中模块为 `capp`，功能名 `improve` 表示完善，开发者缩写为 `MZR`。历史简历上传解析独立功能使用：

```text
feature/capp-resume-upload-parse-MZR
```

每个 feature 分支承载一个完整功能。禁止直接在 `dev`、`main` 开发或推送，禁止 feature 跳过 dev，禁止强推或重写共享分支历史。

## 子功能与原子提交

每个可独立理解、验证和回滚的子功能单独 commit。历史简历上传解析按以下范围拆分，实际提交清单以 PR 为准：

| 子功能 | 范围 |
| --- | --- |
| 协作规范与 memory | 本文档、根目录 AGENTS.md |
| 补齐构建所需的接口源码 | 修复 data 目录误忽略，补入客户端依赖的接口封装 |
| PDF 解析与附件保存 | 逐页文本/OCR、解析配置、私有目录、鉴权读取、事务清理、迁移与相关测试 |
| AI 字段编排 | 模型配置、后端字段提示、宽松转换、自动修正及相关测试 |
| 客户端导入与自动填写 | 文件上传、草稿回填、核对保存、失败重试及相关测试 |
| 功能说明 | 原理、配置、接口、限制和部署说明 |

相关测试随对应子功能提交。历史简历上传解析 PR 不混入岗位推荐等其他功能；当前「完善」交付的授权范围与拆分见下一节。同一文件存在多个子功能修改时，拆分补丁或在独立工作区整理，保留原工作区内容。

提交格式为 `<type>(<scope>): <中文摘要>`。允许的 type 为 `feat`、`fix`、`refactor`、`test`、`docs`、`chore`、`build`、`ci`、`perf`、`revert`；scope 使用 `capp`、`resume`、`backend`、`git` 等稳定模块名。摘要使用祈使语气、描述结果、不加句号，例如：

```text
feat(resume): 支持逐页解析 PDF 并保存私有附件
feat(resume): 按简历字段自动编排识别内容
feat(capp): 自动填入 PDF 简历并支持核对保存
```

必要时在正文写明原因、接口兼容性和验证结果。破坏性变更使用 `!` 并注明 `BREAKING CHANGE:`；关联事项使用 `Refs:` 或 `Closes:`。

## 求职者端完善交付

本次完整功能为完善「岗位发现 → 筛选与推荐 → 投递跟踪 → 面试安排 → 收藏与消息提醒」求职者端闭环，统一使用 `feature/capp-improve-MZR`，最终一个 PR 到 `dev`。不把每个子提交分别创建 PR，也不把无关客户端功能混入。

| 子功能 | 提交范围与验证重点 |
| --- | --- |
| 协作规范与源码忽略规则 | 本文、AGENTS.md；保护私有配置、本机说明和缓存，保留 API 源码 |
| 公共交互基础 | 主题间距与异步状态组件，供当前闭环的业务页复用 |
| 登录失效处理 | HTTP/业务 401、当前会话隔离、去重与登录导航恢复 |
| AI 岗位推荐 | 服务端读取启用的模型 Provider、简历归属、客户端入口与超时；模拟或构建检查不冒充真实模型验收 |
| 岗位组合筛选 | 条件草稿、分页、重试、字段转换及返回保持 |
| 投递跟踪与面试日历 | 复用既有接口、状态映射、日期格式、分页与竞态隔离 |
| 企业主页与收藏提醒 | 公开字段、在招岗位、收藏、发布事务中的提醒及已读状态 |
| 岗位收藏 | 当前用户状态、幂等收藏/取消、分页、下架展示及职位/企业收藏入口 |
| 个人中心与简历入口完善 | 独立简历管理导航、加载隔离与收藏计数刷新 |
| 本机私有 AI 配置模板 | 仅提交无密钥模板与说明，真实配置保持忽略 |

同一文件的共享模型、导航或首页修改按照依赖顺序分阶段提交，相关测试和接口说明随对应子功能。最终 PR 必须列出原子提交、目标分支、验证命令与实际结果、人工验收边界、风险和逐项回滚方式。

开始前 fetch 最新远端。若当前分支落后，不复制整个旧 backend 覆盖最新 dev；从最新 dev 创建独立 worktree，仅迁移当前功能增量，保留远端他人功能和原工作区。提交前对变更内容执行敏感信息检查，只记录命中文件与行号，不输出凭据值。

## 求职者端 AI Agent 交付

完整功能分支为 `feature/capp-agent-MZR`，基于最新 `origin/dev` 创建，全部子功能完成后统一 PR 到 `dev`。范围仅限 C-APP 求职助手与其必要的 Backend 服务，不包含其他客户端或企业端功能。

| 子功能 | 单独提交内容 |
| --- | --- |
| Agent 项目 memory | 本节与根目录 `AGENTS.md`，记录边界、接口、迁移和验证要求 |
| 对话与工具服务 | 会话/消息/运行/事件、模型流式适配、岗位和简历读取工具、鉴权、限额、取消与重连 |
| 自动记忆与摘要 | 账号记忆状态、偏好、会话摘要接口与迁移/回滚 |
| 历史会话操作 | 置顶、重命名、批量删除、生成中任务保护及迁移/回滚 |
| 求职任务上下文 | 岗位推荐、简历分析、面试准备等动作；服务端复核投递与关联简历，迁移/回滚 |
| C-APP 对话体验 | 鉴权 SSE、重试/停止/恢复、历史会话、Markdown、岗位/简历选择、消息页悬浮入口及测试 |
| 接口与部署说明 | API、模型 Provider 条件、配置边界、部署和回滚说明，不包含任何真实密钥 |

四份 SQL 按顺序执行：`migration_capp_ai_agent_20261020.sql`、`migration_capp_ai_memory_20261021.sql`、`migration_capp_ai_history_actions_20261021.sql`、`migration_capp_ai_task_context_20261021.sql`。分别对应 `rollback_capp_ai_agent_20261020.sql`、`rollback_capp_ai_memory_20261021.sql`、`rollback_capp_ai_history_actions_20261021.sql`、`rollback_capp_ai_task_context_20261021.sql`。不修改简历或投递业务表。

Backend 验证执行 Agent Controller、Service/工具、模型流式处理相关 Maven 测试，并检查 Mapper 与迁移字段一致。Flutter 执行 Agent/SSE/历史/上下文选择相关测试及 `flutter analyze`；交付前按环境执行 Android Debug 构建。模拟模型和 H2 测试不代替真实 Provider、目标 MySQL 或设备接口验收；未完成的必要验收在 PR 中列为 Draft 边界。

仅通过环境变量或本机忽略配置提供模型密钥。`backend/config/application.yml`、数据库凭据、真实会话和简历内容不得提交或写入日志。迁移必须可重复检查，回滚先回滚应用代码；删除 AI 数据前备份并说明会清除的会话/记忆数据。

## 提交前检查

先检查当前分支、远端和工作区，再检查 `git diff`、`git diff --cached` 和待提交文件清单。只暂存本子功能的明确路径，不使用全仓暂存夹带无关文件。

禁止提交密码、Token、私钥、数据库凭据、真实个人简历、上传目录、日志、构建产物及本地专用配置。配置模板仅保留环境变量占位符。根目录 `process.md` 与本机启动说明作为本地开发依据保留。

`c-app/lib/features/*/data/*.dart` 属于源码，必须纳入版本控制。运行时数据目录的忽略规则不得影响源码目录。

## 验证与 PR

每个模块完成后检查接口通断、字段对齐、数据正确性和异常分支。PR 前同步最新 `origin/dev`，解决冲突后重新验证受影响内容。

| 范围 | 必须记录的验证 |
| --- | --- |
| Backend | Maven 编译及相关测试；涉及打包和原生 OCR 时验证打包产物 |
| Flutter | 修改文件格式检查、`flutter analyze`、`flutter test`；文件上传涉及平台能力，补充 Android Debug 构建及设备验证 |
| PDF 存储 | 附件字节、元数据、归属校验、路径边界、普通编辑保留附件、替换和事务回滚 |
| AI 编排 | 使用合成数据验证字段转换、缺失值、响应异常、重试和自动填写；真实服务验证不得输出密钥及原文 |
| 数据库 | 迁移幂等、兼容性及回滚说明；已存在的共享附件字段不得直接删除 |
| 文档 | 相对链接、接口、配置与实际代码一致 |

完整功能完成后统一创建一个 `feature/* -> dev` PR。PR 写明目标、改动范围、接口或数据结构影响、验证命令与结果、人工验收情况、风险和回滚方式。未执行的检查明确标记为未验证，不以单元测试冒充完整人工验收；仍有必要验收待完成时使用 Draft PR。

默认保留原子提交并使用 Rebase merge。分支只有一个有效提交或维护者明确要求时才使用 Squash。合并必须满足人工 Review 和 CI 门禁，AI 不代替人工审核合并。

## Dev 到 Main 与回滚

`dev -> main` 仅用于完整可运行版本：计划内功能已合入、必需 CI 通过、数据库迁移可执行且有回滚路径、配置无明文凭据、后端与客户端可从干净环境构建、核心流程验收通过。功能 PR 完成不代表已满足整项目发布条件。

达到门禁后由维护者创建并审核 `dev -> main` PR。合并 main 后再创建语义化版本标签 `vMAJOR.MINOR.PATCH`。本次交付仅推进到 feature PR，发布与合并需要后续人工审核。

共享分支错误使用 `git revert` 或 Revert PR 回滚。简历功能回滚时先回滚应用代码，保留共享的附件字段和已保存 PDF，避免丢失已有数据。
