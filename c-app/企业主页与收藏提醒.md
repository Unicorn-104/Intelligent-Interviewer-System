# 企业主页、收藏与新岗位提醒

2026-10-16，根工作区完成实现；现按用户授权纳入 `feature/capp-improve-MZR`，以独立子功能提交，完整功能统一 PR 到 `dev`。

## 页面与入口

- 职位详情底部企业卡片、企业动态对话中的企业头像，均进入同一个企业主页。
- 岗位模型保留后端已有的 `companyId`；企业动态从已有 `targetUrl=/companies/{id}` 读取企业 ID，不能将收藏记录的 `sourceId` 当成企业 ID。仅识别本地企业路径，不打开任意外链。
- 主页展示真实企业名称、认证状态、行业、规模、城市、介绍、地址、官网及分页在招职位。没有填写的资料显示空态，不编造企业信息。职位列表复用现有岗位卡片、详情和默认简历投递流程。
- 底部支持收藏和取消收藏，按钮仅显示「收藏企业」或「已收藏」，点击「已收藏」仍可取消。以服务端返回状态为准，提交中禁止重复操作。个人中心「我的收藏」可查看收藏的企业，返回列表后刷新。
- 颜色、卡片、按钮、间距与字体复用 `AppTheme`、`AppColors` 和 `AppSpacing`。支持加载、空列表、请求失败、分页重试和下拉刷新。

## 接口与复用边界

全部接口使用 Bearer Token，用户身份由服务器登录态取得，不接受客户端指定用户 ID。

| 方法 | 路径 | 数据 |
|---|---|---|
| GET | `/app/companies/{companyId}` | `id/name/logoUrl/industry/size/city/address/website/intro/verified/followed` |
| GET | `/app/companies/{companyId}/jobs?page=1&size=10` | 复用 `AgentPage<AgentJob>`，返回 `items/page/size/total/hasNext` |
| PUT | `/app/companies/{companyId}/follow` | JSON `{"followed":true}` 或 `false`，返回服务器确认的 `data.followed` |
| GET | `/app/companies/favorites?page=1&size=20` | 当前用户有效收藏的正常企业，返回分页元数据 |

企业查询使用现有 `t_cmp` 的公开招聘字段，复用 `Company` 模型；不直接暴露需要管理权限的 `/system/company/{id}`。旧管理查询依赖本机缺失的 `api_quota/api_used`，本模块通过公开字段投影兼容，不修改管理端或补无关数据库字段。不存在、已下架企业返回业务码 404；服务器诊断信息转换为简明重试提示。

在招职位复用 `IAgentJobService.selectJobs`，给现有 `AgentJobQuery` 添加可选 `companyId`，在 Mapper 中按公司 ID 精确过滤。仅返回正常企业的发布中岗位；不使用公司名称模糊搜索来冒充公司职位列表。分页页码从 1 开始，size 范围 1–100。

收藏复用 `t_usr_interest`，固定 `int_target_type=2`。利用已有用户、对象类型、对象 ID 唯一索引幂等更新收藏状态，不新增收藏表或迁移。取消收藏会清除该用户该公司的旧未读提醒，重新收藏不会重新激活旧红点。

## 发布与消息生命周期

- 在 `EnterpriseJobServiceImpl` 的发布事务内，创建发布中岗位，或将已有草稿/暂停岗位切换到发布中时，向当时仍有效收藏该公司的用户写入 `t_msg`。
- 提醒使用已有运营推送类型 `msg_type=4`，链接为 `/companies/{companyId}?positionId={positionId}`；不新增业务枚举。重复请求及重复发布不会对同一用户、同一岗位重复生成提醒。创建草稿、暂停、下线或已取消收藏不会发送新岗位提醒。
- 发布与提醒写入同一事务；事务失败时一起回滚。状态切换先锁定本公司岗位，创建时在同一连接读取新岗位 ID，避免依赖“查询最新岗位”等存在并发歧义的办法。
- 消息中心仍按收藏记录聚合企业动态，`sourceId` 保持收藏 ID；内容优先读取最近岗位提醒，旧关注关系保留原有最新在招岗位展示。历史展示不自动制造未读提醒。
- 未读数由该用户、该公司真实 `t_msg` 未读记录统计；这些记录不会再作为系统通知重复展示。`PUT /app/messages/COMPANY/{interestId}/read` 校验收藏归属后将该公司提醒已读，全部已读接口也覆盖企业提醒。
- 客户端进入消息页、从消息详情返回或 App 恢复前台时刷新；前台每 30 秒检查新消息，后台停止轮询。加载与已读操作有并发隔离，防止旧列表响应把已读状态覆盖回未读。首页红点与底部消息未读数同步。
- 本轮提供 App 内消息提醒；系统推送、短信、邮件和操作系统通知不在本轮实现中。

## 验证

- `mvn -B -ntp -pl ruoyi-admin -am test`：53 项通过，含企业公开字段/当前用户收藏、下架拒绝、公司职位过滤、取消收藏、公司已读与发布触发条件测试。
- `flutter analyze --no-pub`、`flutter test --no-pub`：静态分析通过，40 项测试通过。新增公司 ID 传递、消息目标校验、鉴权与接口契约、服务器错误简化、收藏防重与失败保留、分页去重与重试、过期响应隔离、320 宽 1.4 倍字体等检查。
- `python tools/verify_company_mysql.py`：使用本机环境凭据，在随机命名的独立空 MySQL 测试库复制表结构并执行当前 Mapper SQL；测试结束删除专用测试库，不修改业务库数据。覆盖公开企业投影、收藏幂等、账号隔离、在招岗位过滤、提醒去重、归属/已读/全部已读、取消与重新收藏、事务回滚。数据库凭据不进入源码或输出。
- 后端本地 JAR 打包和重启通过。Android 模拟器已验证职位详情企业卡片与企业动态头像进入企业主页；杭州与北京企业主页均显示各自 2 个在招岗位。取消收藏后重新进入仍为未收藏，随后已恢复原收藏状态。用户截图确认北京企业主页及在招职位显示，并要求收藏按钮简化为「已收藏」。个人中心收藏列表的完整设备走查、企业发布端到 App 收到新岗位提醒的跨端设备链路仍待进一步验收；独立真实 MySQL SQL 验证不替代该设备链路。

## 回滚

只撤销本功能的客户端入口、`features/companies`、企业公开接口与收藏 Mapper，以及岗位发布和消息聚合的对应增量。保留用户其他未提交功能，保留共享的收藏与消息数据。本功能没有数据库结构迁移；回滚不删除共享表、收藏记录或已发送的历史消息。
