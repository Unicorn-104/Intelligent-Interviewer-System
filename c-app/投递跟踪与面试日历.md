## 既有接口调用

均使用现有 `ApiClient` 和 Bearer Token；响应为若依 `code/msg/data`。用户归属由后端从登录态确定，App 不传用户 ID。

| 方法 | 路径 | 入参 | 响应 |
|---|---|---|---|
| GET | `/agent/v1/applications` | `page`、`size`、可选 `status` | `data.items/page/size/total/hasNext` |
| GET | `/agent/v1/applications/{applicationId}` | 真实投递 ID | `data` 投递对象及 `timeline` |
| GET | `/system/conference/schedule` | `from`、`to` | `data` 日程数组 |
| GET | `/system/conference/session/{sessionId}` | 日程返回的非空场次 ID | `data` 场次上下文 |

投递列表每页 10 条，从第 1 页开始。后端允许 `size` 1–100，按 `updatedAt DESC, id DESC` 排序；App 使用 `hasNext` 判断是否继续，失败后重试同一页。PC 当前取第一页 100 条再本地筛选，App 采用后端已有筛选与真实分页，避免超过 100 条时遗漏数据。

“全部”不传 `status`；其余筛选值与后端一致：

| 分组 | 状态码 | 后端文案 |
|---|---|---|
| active | 0 / 1 / 4 | 待处理 / 初筛通过 / 待笔试 |
| interview | 3 / 5 / 6 | 已约面 / 笔试中 / 笔试通过 |
| closed | 2 / 7 / 8 | 初筛淘汰 / 笔试未通过 / 笔试缺考 |

后端还可能返回 `pending` 分组或未知值；App 保留原 `status`，直接展示服务端 `statusText`，使用中性标签兜底，不创造新业务状态。

投递 DTO 保留原字段名：`id/jobTitle/companyName/status/statusText/statusCode/appliedAt/updatedAt/locationText/salaryText/resumeName/matchedScore/timeline`。首页原 `ApplicationSummary` 继续用于摘要，不将不同协议强行合并。

时间线使用 `stage/state/title/description/occurredAt`。`done` 显示已完成，`current/processing` 显示进行中，`closed` 显示已结束，其余按 PC 兜底显示待处理。保留后端节点顺序、标题及原因，不根据投递状态拼装虚拟进度或完成百分比。

日历请求使用可见月份首日到下个月首日，例如 `from=2026-12-01&to=2027-01-01`，区间左闭右开。后端最大允许三个月，当前每次只取一个月，不使用不受支持的分页或状态参数。排序为开始时间、预约 ID 升序。

日历 DTO 保留 `appointmentId/sessionId/positionId/positionTitle/companyName/startAt/endAt/appointmentStatus/sessionStatus/mode/roomToken/statusText`。`sessionId` 可空；这种情况下只显示已有预约信息，不请求 `/session/null`。日程状态直接显示后端 `待面试/待确认/进行中/已结束`。

`mode` 是 AI 与面试官协作模式，不代表线上/线下：1=纯 AI 面试，2=AI + HR 协同面试，3=AI + 多面试官，4=无 AI · 纯人工，文案对照 PC。轮次从详情 `roundNo/totalRounds` 获取，日历不伪造轮次。详情预约时间使用 `appointmentStartAt/appointmentEndAt`，不误用实际开场时间 `startAt`。

## 时间、错误与鉴权

- 请求日期为 `yyyy-MM-dd`，与 PC 相同。
- 投递时间和时间线返回带上海时区偏移的 ISO 8601；与 PC 一样显示其原始钟面时间到分钟，不转换为设备时区而改变日期。
- 日历 `startAt/endAt` 为 SQL 格式化的 `yyyy-MM-dd HH:mm`，没有时区偏移；保留 PC 的日期分组及本地钟面语义，不追加 `Z` 或按 UTC 解析。
- “本月接下来的面试”包含本月尚未开始、未结束的记录及服务端标记进行中的记录；客户端时钟只控制此展示列表，不推导或覆盖业务状态。切换月份不会拉取其他月份的全部数据。
- 统一请求层继续解析网络异常、超时及若依错误。新增的 401 事件只携带当前请求的会话标识，在 App 内触发一次重新登录提示；忽略旧会话错误。确认后复用现有 `signOut` 清理存储及详情路由；不建立第二套 Token 机制，不输出凭据。
- 空结果、初次加载失败、分页失败、详情失败分别提供空态或重试；刷新保留旧数据，筛选/切月丢弃过期响应，销毁后不再更新状态。
