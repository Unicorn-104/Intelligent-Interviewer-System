## 入口与状态

- HR 聊天中的旧版 `【面试邀请…】` 消息转换为可点击卡片。只解析 `/conference-join` 或 `/agent/conference-entry` 中的 room token，不打开消息中的主机、不向该主机发送登录凭据。非法链接保持普通文本。
- 面试日程详情增加「进入面试准备」。通过 room token 或已授权 sessionId 进入；服务端校验后仍要求 `role=CANDIDATE`。
- 准备页展示服务端最新岗位、企业、时间、轮次和模式；用户主动检测摄像头、麦克风及网络，并确认声音输出、提交录制同意后才能继续。
- 纯 AI 模式 1 调用开始接口；模式 2/3/4 先标记本人 ready，轮询等待服务端 sessionStatus=1。客户端不代替面试官开始协同面试。
- 会议页发布本机音视频、订阅面试官画面与远端屏幕共享，提供静音、摄像头开关、重连、题目、字幕、文字作答及二次确认结束。模式 4 隐藏 AI 题目和字幕。
- 切后台关闭采集；回前台不自动打开摄像头，需用户重新连接。退出页面释放音视频和定时器，离开不会自动结束场次。
- 结果来自后端。作答超时不自动重发，必须确认服务端题目进度已推进，避免无幂等键接口重复计数。

## 接口

以下路径前缀均为 `/system/conference`，附带当前登录 Bearer Token：

| 用途 | 接口 |
| --- | --- |
| 校验与身份 | `GET /link/verify?token=…`、`POST /link/join` |
| 场次与准备 | `GET /session/{id}`、`PUT /session/{id}/participant-state`、`POST /session/{id}/consent` |
| 等候与开始 | `GET /session/{id}/waiting-room`、`POST /session/{id}/start` |
| 音视频 | `GET /livekit-token/{id}`、`PUT /session/{id}/media` |
| 会议状态 | `GET /session/{id}/progress`、`POST /session/{id}/heartbeat` |
| 字幕 | `GET /session/{id}/captions`、`GET /session/{id}/asr/status`、`POST /session/{id}/asr/ticket` |
| 作答与结束 | `POST /session/{id}/answers`、`POST /session/{id}/finish`、`GET /session/{id}/result` |

字幕使用同源 `/ws/conference-asr?ticket=…`，从 LiveKit 麦克风轨道取得 16 kHz 单声道 PCM16，每 200 ms 发送一帧。票据和令牌仅在内存使用；识别未配置时展示降级提示，保留音视频面试。

## 平台与验收

### 2026-10-29：与 E-App 对齐会议室 UI

等候室和正式面试采用与 E-App 相同的深色会议界面：顶部岗位、企业、模式与服务端时长，主舞台、本人右上角小窗、远端成员画面与屏幕共享，以及底部静音、视频、翻转、成员、更多和结束操作。成员和会议信息通过底部面板展示；AI 题目固定在舞台下方，文字作答与实时字幕放入面板，模式 4 不展示 AI 功能。保留 C-App 的设备检测和录制同意准备页。

只迁移适用于候选人的 UI，不提供企业端的主持、邀请和人工开场入口。等候室仍由服务端就绪状态驱动；等候时本机采集已释放，媒体操作不可用。离开会议和结束面试保持独立，结束需要确认。作答草稿在切换面板后保留，面试结束时自动收起面板。小屏和文字放大时操作栏改为两行，横屏可滚动。

实现新增 `presentation/conference_room_view.dart`，摄像头翻转复用 LiveKit 现有轨道接口，没有新增插件、后端接口或平台权限。界面截图使用合成场次生成在 `build/interview-ui-review/`，用于布局检查，不代表真实双端音视频验收；实际跨端开场、媒体、字幕与结束仍需使用新的有效面试联调。

本轮 6 项 UI 专项检查通过，覆盖等候权限、音视频按钮、翻转、作答草稿、人工模式、窄屏大字号、横屏以及键盘弹出时服务端结束面试的退出动画；最终全量 156 项测试通过，5 个改动 Dart 文件格式检查通过。输入框由作答面板自行持有和释放，避免会议室切换至结果页时提前释放输入框。

新增 `livekit_client` 和 `permission_handler`。Android 声明相机、麦克风、音频与网络权限；iOS 补充麦克风用途。项目当前使用 Swift Package Manager，权限插件根据 Info.plist 启用对应权限。Windows 环境不能验证 iOS 构建。

权限插件固定为兼容现有 SDK 36 的 `permission_handler 12.0.1`；两个媒体插件的构建脚本复用项目现有 AGP 9.0.1 / Kotlin 2.3.20，避免额外引入旧工具链。

LiveKit 地址要求 WSS，保留 TLS 证书链与主机校验。私有 CA 测试开关只对 API 同源信令，以及 API 同一主机的 `8444/livekit` 会议网关启用项目已有 CA。其他主机、端口或网关路径仍使用系统信任；HTTP API 的证书信任范围保持原样，不关闭证书验证。

2026-10-29 连接排障：实际会议地址由已认证接口返回，使用同主机 `8444/livekit`，此前按 API 443 端口匹配导致私有 CA 未应用。修复后在原场次热更新并重连，运行状态确认 LiveKit 已连接、摄像头和麦克风均已开启。连接错误按证书、超时、入场凭证及媒体通道分别提示，失败时不再一直显示“正在连接”。这不代替双方实际听音、视频及结束流程验收。
